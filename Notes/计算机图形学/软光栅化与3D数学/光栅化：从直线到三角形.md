# 光栅化——从直线到三角形

## 问题 0：手动设置每个像素太痛苦了

在 [[Notes/计算机图形学/像素与渲染管线全貌/像素、帧缓冲与3D渲染管线|像素、帧缓冲与3D渲染管线]] 里，你写了一个双重循环，手动设置每个像素的颜色来生成渐变图。

但如果我想画一条线呢？最 naive 的做法：

```cpp
// 画一条从 (10, 10) 到 (200, 150) 的线
// 需要遍历所有像素，判断每个像素是否在线段上...
for (int y = 0; y < height; y++) {
    for (int x = 0; x < width; x++) {
        if (pixelOnLine(x, y, 10, 10, 200, 150)) {
            image[y * width + x] = {255, 255, 255};
        }
    }
}
```

**问题很明显**：
1. 判断"像素是否在线段上"的代价很高（浮点距离计算）
2. 遍历全屏像素画一条线，99% 的判断都是浪费的
3. 线稍微移动一下，所有计算全部重来

**我们需要什么**：给定线段的两个端点，**自动算出它经过的所有像素**。

这就是**光栅化（Rasterization）**——把连续的几何描述离散化为像素的过程。

## 问题 1：怎么高效地画一条直线？

### 最 naive 的方案：基于直线方程采样

数学上，直线方程是 `y = kx + b`。我们可以让 x 从 x1 走到 x2，计算对应的 y：

```cpp
void drawLineNaive(Image& img, int x1, int y1, int x2, int y2, Color c) {
    float k = (float)(y2 - y1) / (x2 - x1);
    float b = y1 - k * x1;
    for (int x = x1; x <= x2; x++) {
        int y = (int)(k * x + b);
        img.setPixel(x, y, c);
    }
}
```

**立刻发现的问题**：
1. **浮点运算慢**：每个像素都要做乘法和加法
2. **精度累积误差**：浮点数迭代会产生偏差，长直线的末端可能偏离
3. **不适用于陡线**：当 `|k| > 1` 时，y 方向跳跃，线会断开

### 改进：Bresenham 直线算法（只用整数加法）

1962 年，Jack Bresenham 提出一个天才方案：**用决策参数代替浮点运算**。

核心观察：对于平缓直线（0 < 斜率 < 1），每次 x 增加 1，y 要么不变，要么增加 1。选哪个？看哪个离真实直线更近。

```cpp
void drawLineBresenham(Image& img, int x1, int y1, int x2, int y2, Color c) {
    int dx = x2 - x1;
    int dy = y2 - y1;
    int y = y1;
    int e = 0;  // 决策参数（误差积累）
    
    for (int x = x1; x <= x2; x++) {
        img.setPixel(x, y, c);
        e += 2 * dy;        // 累积误差
        if (e >= dx) {      // 偏离超过半个像素
            y++;            // 向上走一步
            e -= 2 * dx;    // 重置误差
        }
    }
}
```

**关键优化**：两边同乘 `2*dx`，消除了所有浮点运算。现在每个像素只需要**整数加法和比较**。

> 这个算法在 GPU 中仍然有用——虽然现代 GPU 的直线光栅化由硬件完成，但 Bresenham 的"增量计算"思想在边缘函数中得到了延续。

## 问题 2：怎么填充一个实心三角形？

画线可以画三角形的边框，但 3D 渲染需要的是**实心填充**的三角形表面。

### 最 naive 的方案：全屏遍历+内外判断

```cpp
for (int y = 0; y < height; y++) {
    for (int x = 0; x < width; x++) {
        if (pointInTriangle(x + 0.5f, y + 0.5f, tri)) {
            image[y * width + x] = color;
        }
    }
}
```

**立刻发现的问题**：遍历全屏效率太低。一个只占画面 10% 的三角形，90% 的判断都是浪费的。

### 改进 1：包围盒优化

只遍历三角形周围的矩形区域：

```cpp
int minX = floor(min(A.x, B.x, C.x));
int maxX = ceil(max(A.x, B.x, C.x));
int minY = floor(min(A.y, B.y, C.y));
int maxY = ceil(max(A.y, B.y, C.y));

for (int y = minY; y <= maxY; y++) {
    for (int x = minX; x <= maxX; x++) {
        if (pointInTriangle(x + 0.5f, y + 0.5f, tri)) {
            image[y * width + x] = color;
        }
    }
}
```

**效果**：对于只占画面 10% 的三角形，只需判断约 10% 的像素。

### 改进 2：叉乘法判断点是否在三角形内

怎么判断点 `P` 是否在三角形 `ABC` 内部？

**几何直觉**：如果 `P` 在三角形内部，那么它一定在三条边的"同一侧"。用叉乘判断：

```cpp
float cross(const Vec2& a, const Vec2& b) {
    return a.x * b.y - a.y * b.x;  // 2D 叉乘 = 有向面积 × 2
}

bool pointInTriangle(const Vec2& p, const Triangle& tri) {
    // 三条边
    Vec2 e1 = tri.p2 - tri.p1;
    Vec2 e2 = tri.p3 - tri.p2;
    Vec2 e3 = tri.p1 - tri.p3;
    // 从顶点指向 P 的向量
    Vec2 v1 = p - tri.p1;
    Vec2 v2 = p - tri.p2;
    Vec2 v3 = p - tri.p3;
    // 三次叉乘
    float c1 = cross(e1, v1);
    float c2 = cross(e2, v2);
    float c3 = cross(e3, v3);
    // 同号则在内部
    bool hasNeg = (c1 < 0) || (c2 < 0) || (c3 < 0);
    bool hasPos = (c1 > 0) || (c2 > 0) || (c3 > 0);
    return !(hasNeg && hasPos);
}
```

## 问题 3：现代 GPU 用什么方法光栅化？

叉乘法能判断"在内/在外"，但它只回答了一个 yes/no 的问题。真正渲染一个三角形时，我们往往还需要回答另一个问题：**这个像素在三角形内部的哪个位置？**

为什么这很重要？因为三角形的三个顶点通常带有不同的颜色、纹理坐标、法线或深度值。像素 P 的颜色不能简单地填成某个顶点的颜色，而应该是三个顶点属性的**加权混合**。离顶点 A 更近的像素，A 的颜色贡献就更大。

这个"权重"就是**重心坐标（Barycentric Coordinates）**。现代 GPU 的光栅化器在判断像素是否在三角形内部的同时，会直接算出重心坐标。做到这一点的方法就是**边缘函数法（Edge Function）**。

### 重心坐标：三角形内部的"位置坐标"

先抛开 GPU，单独理解重心坐标。对于三角形 $ABC$ 内的任意一点 $P$，总可以把它写成三个顶点的加权平均：

$$
P = \alpha A + \beta B + \gamma C
$$

并且满足：

$$
\alpha + \beta + \gamma = 1, \quad \alpha, \beta, \gamma \geq 0
$$

这里的 $(\alpha, \beta, \gamma)$ 就是 $P$ 的重心坐标。

**几何直觉**：这三个权重不是随意凑出来的，它们分别对应三块子三角形的面积比。

- $\alpha$ = 三角形 $PBC$ 的面积 / 三角形 $ABC$ 的面积
- $\beta$ = 三角形 $PAC$ 的面积 / 三角形 $ABC$ 的面积
- $\gamma$ = 三角形 $PAB$ 的面积 / 三角形 $ABC$ 的面积

所以 $P$ 越靠近顶点 $A$，三角形 $PBC$ 就越大，$\alpha$ 也就越大。当 $P$ 正好落在 $A$ 上时，$\alpha = 1$，$\beta = \gamma = 0$。

一旦有了重心坐标，任意顶点属性 $V$（颜色、纹理坐标、深度等）在 $P$ 点的插值结果就是：

```cpp
V_p = alpha * V_a + beta * V_b + gamma * V_c;
```

这就是 GPU 能做颜色渐变、纹理贴图和光照插值的基础。

### 边缘函数：把"内外判断"和"面积计算"合二为一

现在的问题是：怎么高效地算出 $\alpha, \beta, \gamma$？

最朴素的想法是：先用叉乘法判断 $P$ 在三角形内部，再额外用面积公式算三个子面积，最后得到重心坐标。这样每个像素要做两套独立计算，效率不高。

边缘函数的巧妙之处在于：**判断点 $P$ 在边哪一侧所用的量，正好就是重心坐标需要的子面积**。

对于三角形的一条边，比如从 $P_1(x_1, y_1)$ 到 $P_2(x_2, y_2)$，边缘函数定义为：

$$
E(x, y) = (x_2 - x_1)(y - y_1) - (y_2 - y_1)(x - x_1)
$$

写成向量形式就是：

```
E(x, y) = cross(P2 - P1, P - P1)
```

这个式子有两层含义：

1. **符号含义**：$E(x, y) > 0$ 表示 $P$ 在边 $P_1P_2$ 的一侧，$E(x, y) < 0$ 表示在另一侧，$E(x, y) = 0$ 表示正好在边上。这正是叉乘法判断内外的核心。
2. **大小含义**：$|E(x, y)|$ 等于"以 $P_1P_2$ 为底、$P$ 为顶点"的三角形面积的 **两倍**。

第二层含义是关键。它意味着边缘函数值本身就是重心坐标公式里的分子。

### 从边缘函数到重心坐标

假设三角形三个顶点为 $A, B, C$。我们按一致的方向（比如逆时针）定义三条边的边缘函数：

```cpp
// 边 BC，对应顶点 A 的子面积
e_a = cross(C - B, P - B);

// 边 CA，对应顶点 B 的子面积
e_b = cross(A - C, P - C);

// 边 AB，对应顶点 C 的子面积
e_c = cross(B - A, P - A);
```

注意这里的对应关系：

- $e_a$ 是边 $BC$ 对应的边缘函数，它度量的是三角形 $PBC$ 的有向面积，也就是顶点 $A$ 对面的子三角形面积。所以 $e_a$ 对应 $\alpha$。
- 同理，$e_b$ 对应 $\beta$，$e_c$ 对应 $\gamma$。

总面积的两倍是：

```cpp
float area2 = e_a + e_b + e_c;  // 等于三角形 ABC 有向面积的两倍
```

于是重心坐标就是：

```cpp
float alpha = e_a / area2;  // 顶点 A 的权重
float beta  = e_b / area2;  // 顶点 B 的权重
float gamma = e_c / area2;  // 顶点 C 的权重
```

现在你看出了边缘函数法的优雅之处：

- **判断内外**：三个边缘函数值是否同号（相对于总面积的符号）。
- **计算权重**：三个边缘函数值直接除以总面积。

同一组计算，同时解决了两个问题。

> 如果三角形顶点是顺时针排列，`area2` 会为负，三个 `e_*` 也会同时为负，相除后权重仍然是正的。实际代码中通常用 `e * area2 >= 0` 来判断同号，符号方向不影响最终结果。

### 关键优势 1：增量计算

边缘函数是 $x$ 和 $y$ 的线性函数，这是它能被 GPU 硬件高效实现的根本原因。

当像素从 $(x, y)$ 移动到相邻像素 $(x+1, y)$ 时，边缘函数值的变化只和边的 $y$ 跨度有关：

```cpp
E(x+1, y) = E(x, y) + (y1 - y2)  // 沿 X 方向：加 (y1 - y2)
```

当移动到 $(x, y+1)$ 时，变化只和边的 $x$ 跨度有关：

```cpp
E(x, y+1) = E(x, y) + (x2 - x1)  // 沿 Y 方向：加 (x2 - x1)
```

这意味着：扫描一行像素时，第一个像素用完整公式算出三个边缘函数值，之后每向右移动一个像素，每个边缘函数只需要 **一次加法**。三个边缘函数就是三次加法。

| 计算方式 | 每个像素需要做什么 | 100×100 包围盒 |
|----------|------------------|---------------|
| 朴素叉乘 | 三次完整叉乘：每次 2 次减法、2 次乘法、1 次减法 | 约 150,000 次运算 |
| 边缘函数增量 | 初始一次完整计算，之后每个像素 3 次加法 | 约 30,000 次加法 |

> 这里统计的是光栅化核心循环内的运算。包围盒、初始值等开销两者都有，不纳入对比。

### 关键优势 2：内外判断和属性插值一体化

叉乘法只能告诉你"在内"还是"在外"。如果还想要重心坐标做插值，你必须再写一套面积计算。

边缘函数法则把这两件事合在了一起：

```cpp
// 同一组 e_a, e_b, e_c
// 用乘法判断同号，避免单独处理正负方向
bool inside = (e_a * area2 >= 0) &&
              (e_b * area2 >= 0) &&
              (e_c * area2 >= 0);

float alpha = e_a / area2;
float beta  = e_b / area2;
float gamma = e_c / area2;
```

对 GPU 来说，这意味着光栅化器只需要一套硬件电路，就能同时输出"这个像素要不要着色"和"如果要着色，它的插值权重是什么"。颜色、纹理坐标、深度、法线……所有顶点属性的插值都基于同一组 $(\alpha, \beta, \gamma)$。

### 与传统方法的对比

| 维度 | 全屏遍历 + 叉乘 | 包围盒 + 叉乘 | 包围盒 + 边缘函数 |
|------|----------------|--------------|------------------|
| 遍历范围 | 整个屏幕 | 三角形包围盒 | 三角形包围盒 |
| 内外判断 | 三次叉乘/像素 | 三次叉乘/像素 | 三次加法/像素（增量） |
| 能否直接插值 | 不能，需额外计算 | 不能，需额外计算 | **能，边缘函数值即权重分子** |
| 现代 GPU 使用 | 否 | 软件光栅教学 | **硬件标准实现** |

### 一个具体例子

假设三角形顶点为 $A(1, 1), B(5, 1), C(3, 4)$，像素中心 $P(3, 2)$。

先算 $e_a$（边 $BC$，对应顶点 $A$）：

```
e_a = cross(C - B, P - B)
    = cross((3-5, 4-1), (3-5, 2-1))
    = cross((-2, 3), (-2, 1))
    = (-2)*1 - 3*(-2) = -2 + 6 = 4
```

再算 $e_b$（边 $CA$，对应顶点 $B$）：

```
e_b = cross(A - C, P - C)
    = cross((1-3, 1-4), (3-3, 2-4))
    = cross((-2, -3), (0, -2))
    = (-2)*(-2) - (-3)*0 = 4
```

最后算 $e_c$（边 $AB$，对应顶点 $C$）：

```
e_c = cross(B - A, P - A)
    = cross((5-1, 1-1), (3-1, 2-1))
    = cross((4, 0), (2, 1))
    = 4*1 - 0*2 = 4
```

总面积的两倍：

```
area2 = cross(B - A, C - A)
      = cross((5-1, 1-1), (3-1, 4-1))
      = cross((4, 0), (2, 3))
      = 4*3 - 0*2 = 12
```

三个边缘函数都与 `area2` 同号（都是正数），所以 $P$ 在三角形内部。

重心坐标：

```
alpha = e_a / area2 = 4 / 12 = 1/3
beta  = e_b / area2 = 4 / 12 = 1/3
gamma = e_c / area2 = 4 / 12 = 1/3
```

$P$ 正好是这个三角形的重心，三个权重相等。你可以把它代入 $P = \alpha A + \beta B + \gamma C$ 验证：

```
(1/3)*(1,1) + (1/3)*(5,1) + (1/3)*(3,4) = (3, 2) = P
```

> 这个例子按 $A \to B \to C$ 是逆时针排列，所以 `area2` 为正。如果顶点顺序反过来变成顺时针，`area2` 和三个 `e_*` 都会变成负数，但 `e_* / area2` 的比值不变，权重仍然是正的。实际代码中通常用 `e * area2 >= 0` 来判断同号，而不直接判断 `e > 0`。

## 完整光栅化代码

```cpp
void rasterizeTriangle(Image& img, Vertex v[3]) {
    // 1. 计算总面积
    float area2 = cross2D(v[1].pos - v[0].pos, v[2].pos - v[0].pos);
    if (fabs(area2) < 1e-6) return;
    
    // 2. 计算包围盒
    int minX = std::max(0, (int)floor(min({v[0].pos.x, v[1].pos.x, v[2].pos.x})));
    int maxX = std::min(img.width-1, (int)ceil(max({v[0].pos.x, v[1].pos.x, v[2].pos.x})));
    int minY = std::max(0, (int)floor(min({v[0].pos.y, v[1].pos.y, v[2].pos.y})));
    int maxY = std::min(img.height-1, (int)ceil(max({v[0].pos.y, v[1].pos.y, v[2].pos.y})));
    
    // 3. 预计算增量步长
    float edge01StepX = v[0].pos.y - v[1].pos.y;
    float edge12StepX = v[1].pos.y - v[2].pos.y;
    float edge20StepX = v[2].pos.y - v[0].pos.y;
    
    // 4. 光栅化循环
    for (int y = minY; y <= maxY; y++) {
        Vec2 p = {minX + 0.5f, y + 0.5f};
        float e01 = cross2D(v[1].pos - v[0].pos, p - v[0].pos);
        float e12 = cross2D(v[2].pos - v[1].pos, p - v[1].pos);
        float e20 = cross2D(v[0].pos - v[2].pos, p - v[2].pos);
        
        for (int x = minX; x <= maxX; x++) {
            // 用 area2 统一符号判断
            bool inside = (e01 * area2 >= 0) && (e12 * area2 >= 0) && (e20 * area2 >= 0);
            
            if (inside) {
                float alpha = e12 / area2;
                float beta  = e20 / area2;
                float gamma = e01 / area2;
                
                // 颜色插值
                Color c = {
                    (uint8_t)(alpha * v[0].color.r + beta * v[1].color.r + gamma * v[2].color.r),
                    (uint8_t)(alpha * v[0].color.g + beta * v[1].color.g + gamma * v[2].color.g),
                    (uint8_t)(alpha * v[0].color.b + beta * v[1].color.b + gamma * v[2].color.b),
                    255
                };
                img.setPixel(x, y, c);
            }
            
            e01 += edge01StepX;
            e12 += edge12StepX;
            e20 += edge20StepX;
        }
    }
}
```
