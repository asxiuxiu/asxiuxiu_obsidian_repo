# 变换续——视图与投影

## 问题 0：模型摆好了，怎么"拍照"？

在 [[Notes/计算机图形学/软光栅化与3D数学/3D变换与齐次坐标|3D变换与齐次坐标]] 中，我们用模型矩阵把物体从局部坐标摆到了世界坐标。但 3D 场景里有无数物体，屏幕只有那么大。

**核心问题**：怎么把 3D 世界"拍"成 2D 照片？

需要两个变换：
1. **视图变换（View）**：把相机架到标准位置
2. **投影变换（Projection）**：把 3D 场景"拍扁"成 2D

---

## 问题 1：视图变换——怎么把相机移回原点？

### 核心观察

如果相机和物体的**相对位置**不变，渲染结果就不变。

**策略**：把相机移动到标准位置，其他物体跟着一起动。

**标准相机配置**：
- 位置：原点 `(0, 0, 0)`
- 朝向：`-Z` 方向（看向屏幕里面）
- 上方：`+Y` 方向

### 用三个参数定义相机

| 参数 | 符号 | 含义 |
|-----|------|------|
| 位置 | `eye` | 相机在哪 |
| 朝向 | `target` | 看向哪里 |
| 上方 | `up` | 相机的上方向 |

### 视图矩阵推导

**步骤 1：平移相机到原点**

```
T_view = Translate(-eye.x, -eye.y, -eye.z)
```

**步骤 2：旋转相机到标准朝向**

需要把相机的坐标轴 `(right, up, -forward)` 旋转到世界坐标轴 `(X, Y, Z)`。

先计算相机的三个轴：

```cpp
Vec3 forward = Normalize(target - eye);    // 相机看向的方向
Vec3 right   = Normalize(Cross(forward, up)); // 右方向
Vec3 newUp   = Cross(right, forward);       // 重新计算正交的上方向
```

视图矩阵：

```cpp
Mat4 LookAt(Vec3 eye, Vec3 target, Vec3 up) {
    Vec3 f = Normalize(target - eye);
    Vec3 r = Normalize(Cross(f, up));
    Vec3 u = Cross(r, f);
    
    Mat4 view = {
        { r.x,  r.y,  r.z, -Dot(r, eye) },
        { u.x,  u.y,  u.z, -Dot(u, eye) },
        { -f.x, -f.y, -f.z, Dot(f, eye) },
        { 0,    0,    0,    1           }
    };
    return view;
}
```

> 记忆要点：先平移再旋转，矩阵乘法从右到左。`view = R × T`。

## 问题 2：投影——怎么把3D"拍扁"成2D？

### 两种投影方式

| 类型       | 特点            | 应用                 |
| -------- | ------------- | ------------------ |
| **正交投影** | 平行线保持平行，无近大远小 | 工程制图、2D 游戏、策略游戏小地图 |
| **透视投影** | 近大远小，符合人眼视觉   | 3D 游戏、写实渲染         |

### 正交投影

本质：**先平移中心到原点，再缩放到 `[-1, 1]` 的标准范围**。

```
M_ortho = S_ortho × T_ortho

其中：
T_ortho = Translate(-(r+l)/2, -(t+b)/2, -(n+f)/2)
S_ortho = Scale(2/(r-l), 2/(t-b), 2/(n-f))
```

> 注意：`n > f`（相机看向 `-Z`，近平面离相机更近，`z` 值更大）

### 透视投影（核心难点）

透视投影的目标：把**视锥体**（金字塔形状）映射到**标准立方体** `[-1, 1]³`。

#### 核心思想：两步走

1. **挤压**：把视锥体"挤压"成一个长方体
2. **正交投影**：把长方体映射到标准立方体（这个我们已经会了）

#### 为什么"挤压"能用矩阵表示？

直接做需要除以 `z`：

```
x' = (n/z) × x
y' = (n/z) × y
```

这是**非线性**操作，普通矩阵无法实现。

**齐次坐标的巧妙**：把 `z` 存入 `w` 分量，等矩阵运算结束后再做**透视除法**（除以 `w`）。

```
4D点 (x, y, z, 1)
    │ 乘以 4×4 矩阵（纯线性运算）
    ▼
4D点 (nx, ny, Az+B, z)  ← z 被存入了 w 分量
    │ 透视除法（除以 w=z）
    ▼
3D点 (nx/z, ny/z, (Az+B)/z)
```

#### 挤压矩阵

利用两个约束条件求解第三行：
- 近平面 `z=n` 不变 → `An + B = n²`
- 远平面中心 `z=f` 不变 → `Af + B = f²`

解得：`A = n + f`，`B = -nf`

```
| n   0   0    0 |
| 0   n   0    0 |
| 0   0  n+f  -nf |
| 0   0   1    0 |
```

#### 完整透视投影矩阵

```
M_persp = M_ortho × M_persp→ortho
```

用 FOV 和 Aspect 定义视锥体：

```cpp
Mat4 Perspective(float fovY, float aspect, float near, float far) {
    float top = near * tan(fovY * PI / 360.0f);
    float right = top * aspect;
    
    Mat4 persp = {
        { near/right, 0,          0,                      0 },
        { 0,          near/top,   0,                      0 },
        { 0,          0,          (near+far)/(near-far),  2*near*far/(near-far) },
        { 0,          0,         -1,                      0 }
    };
    return persp;
}
```

## 问题 3：裁剪空间——投影之后、NDC 之前

到这一步，我们已经能把相机空间的点变成一个四维齐次坐标 $(x_c, y_c, z_c, w_c)$。但它还不是屏幕上可见的像素。这里有几个最常见的误解，需要一个个拆开。

### 3.1 误解 1：投影之后，z 应该变成 0 了吧？

并不是。3D 渲染里的"投影"不是简单地把点拍成 2D 然后丢掉深度。

如果只保留 $x, y$，两个三角形重叠时 GPU 就完全不知道谁在前面、谁在后面。所以投影矩阵会**把 $z$ 重新编码成一个深度值**：经过透视除法后得到 $z_{ndc} \in [-1, 1]$，这就是后面 [[Notes/计算机图形学/软光栅化与3D数学/3D光栅化与深度缓冲|Z-Buffer]] 用来比较远近的深度。

所以在透视投影矩阵输出的四维点中：

- $x_c, y_c$ 负责"这个点在屏幕上的哪个方向"；
- $z_c$ 负责"这个点离相机多远"；
- $w_c = -z_e$ 负责"暂存将来要除的 $z$"。

为什么 $w_c$ 一定是 $-z_e$？看投影矩阵的最后一行：

```cpp
{ 0, 0, -1, 0 }
```

矩阵乘向量的第四分量就是这一行与 $(x_e, y_e, z_e, 1)$ 的点积：

$$
w_c = 0 \cdot x_e + 0 \cdot y_e + (-1) \cdot z_e + 0 \cdot 1 = -z_e
$$

所以这不是碰巧，而是矩阵**故意这样设计**的。因为相机看向 $-Z$，面前点的 $z_e$ 是负数，$w_c = -z_e$ 就是正数，后面做透视除法才安全。

> 一句话：**投影之后 z 没有消失，只是从"距离"变成了"深度值"**。

### 3.2 误解 2：投影矩阵把整个场景都塞进了 [-1,1]³？

这也是一个很容易产生的直觉：场景里有无数个点，怎么可能全部压缩进大小为 1 的立方体？

答案是：**不是整个场景，只有视锥体**。

投影矩阵的几何意义，是把相机面前那个**有限的视锥体**映射到标准立方体 $[-1,1]^3$。视锥体由 `fovY`、`aspect`、`near`、`far` 定义，它只截取世界中的一小块空间：

```text
世界空间：整个场景无限大
    │
    ▼
相机空间：整个场景被变换到相机坐标系
    │
    ▼
视锥体：只保留相机能看到的那个四棱台区域
    │
    ▼
投影矩阵：把四棱台映射到 [-1,1]³
```

视锥体外的**顶点**也会被乘上同一个投影矩阵，但它们**不会**落到 $[-1,1]^3$ 里，而是落在裁剪空间 $[-w,w]^3$ 的外面。单个顶点只有两种命运：在内保留，在外丢弃。

但 GPU 裁剪的基本单位是**三角形**，不是单个顶点。如果整个三角形都在外，直接丢弃；如果三角形只有一部分在外，GPU 会沿着裁剪平面把它切成一个更小的三角形（或四边形再拆成两个三角形），只保留在盒子里的部分。

> 一句话：**投影矩阵是统一作用到所有顶点的，但结果不是让所有顶点都可见；它只是给出一个统一的坐标系，让 GPU 能简单地判断哪些顶点/三角形看得见、哪些看不见。**

### 3.3 一个具体例子：点 A 在内部，点 B 在外部

假设相机看向 $-Z$，近平面 $n=1$，远平面 $f=100$，右平面在近平面上的半宽 $right=1$。透视投影矩阵第一行是 $near/right = 1$，最后一行是 $[0, 0, -1, 0]$，所以 $w_c = -z_e$。

- **点 A**：相机空间 $(0.5, 0.5, -2, 1)$，在视锥体内部。
  - $w_c = 2$，$x_c = 1 \cdot 0.5 = 0.5$。
  - 检查：$-2 \le 0.5 \le 2$，在范围内，保留。
  - 透视除法后：$x_{ndc} = 0.5 / 2 = 0.25$，落在 $[-1, 1]$ 内。

- **点 B**：相机空间 $(5, 0.5, -2, 1)$，在视锥体右侧外面。
  - $w_c = 2$，$x_c = 1 \cdot 5 = 5$。
  - 检查：$5 > w_c = 2$，在右平面外，丢弃。

看到了吗？**点 B 乘了同样的矩阵，只是算出来落在盒子外面，所以被裁掉**。它不会出现在屏幕上，但变换过程本身和点 A 完全一样，这正是 GPU 并行处理的前提。

### 3.4 为什么透视除法非得是"除法"？

因为"拍扁"在几何上本来就是**除以距离**。

相机在原点，看向 $-Z$，成像平面在 $z=-n$。对相机空间中任意一点 $(x_e, y_e, z_e)$，从相机到该点的光线与成像平面的交点，由相似三角形可得：

$$
x_i = n \cdot \frac{x_e}{-z_e}, \quad y_i = n \cdot \frac{y_e}{-z_e}
$$

也就是说，对**横向偏移 $x_e$ 相同**的两个点，越深（$-z_e$ 越大），$x_i$ 的绝对值越小，在成像平面上的位置就越靠近中心。这就是“近大远小”——同样宽度的物体，越远看起来越窄，边缘越往中间收。

注意这个结论有两个前提：

1. 它说的是**固定横向偏移 $x_e$、改变深度**的情况，不是“沿同一根视线往远处走”。沿同一根视线走时，$x_e / (-z_e)$ 不变，投影位置其实不变。
2. 如果点本身很偏，导致 $|x_i| > right$，那它根本不在成像平面（视锥体）内，会被裁剪掉，自然谈不上“投影到中心”。

投影矩阵做的是：

$$
x_c = \frac{n}{right} \cdot x_e, \quad y_c = \frac{n}{top} \cdot y_e, \quad w_c = -z_e
$$

然后透视除法：

$$
\frac{x_c}{w_c} = \frac{n/right \cdot x_e}{-z_e} = \frac{n}{right} \cdot \frac{x_e}{-z_e}
$$

正好就是相似三角形的结果，再被 $right/top$ 归一化到 $[-1, 1]$。

所以**除以 $w$ 不是随便选的，它就是"除以距离 $-z$"的齐次坐标写法**。而 $z$ 在除完之后变成 $z_{ndc}$，用于深度缓冲，所以不能提前抹掉。

> **常见疑问**：投影后的四维点是 $(x, y, z, -z)$ 吗？
> 
> 不是。第四分量 $w_c = -z_e$，但第三分量 $z_c = A \cdot z_e + B$（是 $z_e$ 的线性函数），两者一般不相等。保留不同的 $z_c$ 正是为了透视除法后得到可变的深度值 $z_{ndc} = z_c / w_c$；如果 $z_c = w_c$，所有点的 $z_{ndc}$ 都将是常数，Z-Buffer 就失效了。

### 3.5 裁剪空间的正式定义

对相机空间中的点 $\mathbf{p}_e = (x_e, y_e, z_e, 1)$，乘上透视投影矩阵 $\mathbf{M}_{persp}$ 后得到：

$$
\mathbf{p}_c = \mathbf{M}_{persp} \cdot \mathbf{p}_e = (x_c, y_c, z_c, w_c)
$$

这个 $\mathbf{p}_c$ 就是该点在**裁剪空间**中的表示。在 OpenGL 约定下，点位于视锥体内部当且仅当：

$$
-w_c \le x_c, y_c, z_c \le w_c
$$

这六个不等式对应视锥体的六个面：

| 裁剪空间边界 | 对应视锥体面 |
|---|---|
| $x_c = w_c$ | 右平面 |
| $x_c = -w_c$ | 左平面 |
| $y_c = w_c$ | 上平面 |
| $y_c = -w_c$ | 下平面 |
| $z_c = -w_c$ | 近平面 |
| $z_c = w_c$ | 远平面 |

> 表格只用于总结：这里只是把"相机空间中的斜平面"和"裁剪空间中的坐标平面"对应起来。

### 3.6 为什么叫"裁剪空间"？

因为 GPU 在这个阶段真正执行**裁剪（Clipping）**：

- 完全在外的三角形 → 直接丢弃；
- 部分在外的三角形 → 沿着 $x=\pm w, y=\pm w, z=\pm w$ 这些坐标平面切成小三角形；
- 保留下来的部分再做透视除法：

$$
x_{ndc} = \frac{x_c}{w_c}, \quad y_{ndc} = \frac{y_c}{w_c}, \quad z_{ndc} = \frac{z_c}{w_c}
$$

得到 **NDC（Normalized Device Coordinates）** $[-1, 1]^3$。

> **一句话总结**：裁剪空间是投影矩阵输出后、透视除法之前的一个中间站。它让所有顶点都进入同一个"齐次盒子"，用简单的坐标比较完成裁剪，同时保留 $z$ 作为深度，为下一步的 Z-Buffer 做准备。

## 问题 4：MVP 变换的完整链路

```
模型空间 ──[M]──→ 世界空间 ──[V]──→ 相机空间 ──[P]──→ 裁剪空间 ──[透视除法]──→ NDC ──[视口]──→ 屏幕空间
 (局部)            (全局)            (视角)            [-w,w]³            [-1,1]³            [0,width]
                                                                                         [0,height]
```

```cpp
// 完整变换
Mat4 MVP = P * V * M;  // 从右往左：先 Model，再 View，再 Projection
Vec4 clip = MVP * Vec4(x, y, z, 1);
Vec3 ndc = Vec3(clip.x, clip.y, clip.z) / clip.w;  // 透视除法：每个顶点除自己的 w
Vec2 screen = Vec2(
    (ndc.x + 1) * 0.5 * width,
    (ndc.y + 1) * 0.5 * height
);
```

这里 `clip` 就是裁剪空间中的四维齐次坐标。注意它还没有被归一化：$x, y, z$ 的"合法范围"是 $\pm w$，而不是 $\pm 1$。GPU 会先用这六个不等式把三角形裁好，再把结果除以 `clip.w`，才得到 NDC。

**每个顶点除自己的 $w$**：因为每个点的 $w_c = -z_e$ 只由它自己的深度决定，所以透视除法天然是按顶点独立进行的。顶点 A 除 A 的 $w$，顶点 B 除 B 的 $w$，互不干扰。现代 GPU 的顶点着色器正是利用这一点，对成千上万个顶点并行执行同一套变换。

对软渲染器来说，你可以选择在透视除法之后再做屏幕映射，也可以先按裁剪空间的范围剔除完全不可见的三角形，两者等价；现代 GPU 之所以保留齐次裁剪这一步，是因为裁剪只需要简单的坐标比较，而透视除法本身是非线性的，不能放进 $4 \times 4$ 矩阵。
