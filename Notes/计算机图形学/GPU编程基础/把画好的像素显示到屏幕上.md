# 把画好的像素显示到屏幕上

## 问题 0：GPU 画完了，为什么屏幕上还没出现？

在软渲染器里，你写完 `framebuffer[x, y] = color` 后，数据就在内存里了。如果你把 PPM 文件保存下来，结果就是最终的图像。

但 GPU 渲染的目标是**屏幕上的窗口**。GPU 画完后，窗口里的像素不会自动更新。中间还隔着几个步骤：

```
GPU 渲染目标（后台缓冲）
        ↓
   交换链切换
        ↓
   窗口表面（Surface）
        ↓
   显示控制器读取
        ↓
   物理屏幕刷新
```

如果这几个步骤没有协调好，就会出现**画面撕裂**。

---

## 问题 1：什么是画面撕裂？

画面撕裂（Tearing）是指屏幕上半部分显示旧帧，下半部分显示新帧。

**为什么会这样？**

显示器不是一次性显示整帧图像，而是从上到下逐行扫描。扫描一帧的时间由刷新率决定：
- 60Hz 显示器：约 16.67ms 扫描完一帧
- 144Hz 显示器：约 6.94ms 扫描完一帧

如果 GPU 在显示器扫描到一半时更新了帧缓冲，显示器就会：
- 上半部分读到旧帧
- 下半部分读到新帧

这就是撕裂。

---

## 问题 2：双缓冲怎么解决撕裂？

**双缓冲（Double Buffering）**：GPU 同时维护两个帧缓冲：
- **前台缓冲（Front Buffer）**：当前正在显示到屏幕
- **后台缓冲（Back Buffer）**：GPU 正在画

GPU 只在后台缓冲上绘制。画完后，交换前后台缓冲的角色。

```
帧 N：
  CPU/GPU 在 Back Buffer 画
  Front Buffer 正在显示

画完后：
  交换两者角色
  新的 Front Buffer = 刚才画好的 Back Buffer
  新的 Back Buffer = 旧的 Front Buffer（下一帧覆盖绘制）
```

但双缓冲本身不能完全避免撕裂。如果在显示器扫描到一半时交换缓冲，仍然可能撕裂。

---

## 问题 3：VSync 怎么解决撕裂？

**VSync（Vertical Synchronization）**：只在显示器完成一帧扫描后（垂直空白期，V-Blank）才交换缓冲。

```
显示器扫描：
  [第 N 帧显示中] [V-Blank] [第 N+1 帧显示中] [V-Blank]
                    ↑
              只允许在这里交换缓冲
```

这样保证显示器开始显示新一帧时，看到的是完整的一帧。

OpenGL 里开启 VSync：
```cpp
glfwSwapInterval(1);  // 1 = 开启 VSync，0 = 关闭
```

---

## 问题 4：VSync 开启后，帧率为什么会被锁到 60 / 144？

如果显示器刷新率是 60Hz，VSync 会把 GPU 的帧率限制为 60fps 的约数：
- 60fps：每帧在 16.67ms 内完成，刚好赶上一次刷新
- 30fps：如果一帧没完成，就等到下一次刷新，变成 30fps

这就是**VSync 锁帧**。

**为什么 FPS 计数器可能测"假数据"？**

如果你的 GPU 实际能在 8ms 内画完一帧（理论 125fps），但 VSync 把它锁到 60fps，那 FPS 计数器显示 60fps 并不代表 GPU 只能跑 60fps。它只是被显示器刷新率限制了。

---

## 问题 5：G-Sync / FreeSync 是什么？

VSync 的问题是：它强制 GPU 等待显示器，导致输入延迟增加，而且帧率只能取刷新率的约数。

**G-Sync（NVIDIA）** 和 **FreeSync（AMD）** 让显示器**适应 GPU**：
- 显示器不固定 60Hz/144Hz，而是等 GPU 画完一帧后再刷新
- 这样 GPU 跑 73fps，显示器就显示 73fps

这消除了撕裂，同时减少了输入延迟。

---

## 问题 6：交换链是什么？

在 GPU 编程里，**交换链（Swap Chain）** 是管理前后台缓冲的对象。

OpenGL 里，`glfwSwapBuffers()` 隐式管理了交换链。但在 Vulkan/D3D12/Metal 里，你必须显式创建 `VkSwapchainKHR` / `IDXGISwapChain` / `CAMetalDrawable`。

交换链负责：
1. 提供多个缓冲图像（通常是 2 或 3 个）
2. 在 V-Blank 时交换图像
3. 处理窗口 Resize 时重建缓冲

---

## 问题 7：三缓冲有什么好处？

双缓冲下，如果 GPU 画完一帧时错过了 V-Blank，它必须等下一次刷新，CPU/GPU 空等。

三缓冲（Triple Buffering）增加一个额外缓冲：
- GPU 可以在一个缓冲上画
- 另一个缓冲已经画好，等待显示
- 还有一个缓冲正在被显示

这样 GPU 不需要等待显示器，可以持续工作，减少空闲时间。

代价：增加一帧的延迟和显存占用。

---

## 问题 8：怎么测量真实 GPU 性能？

如果你的帧率被 VSync 锁定，FPS 计数器不能反映 GPU 真实能力。应该用 GPU 时间戳（GPU Timestamp）测量：

```cpp
// OpenGL 查询
GLuint query;
glGenQueries(1, &query);

glBeginQuery(GL_TIME_ELAPSED, query);
// ... 绘制 ...
glEndQuery(GL_TIME_ELAPSED);

GLuint64 elapsed;
glGetQueryObjectui64v(query, GL_QUERY_RESULT, &elapsed);
float ms = elapsed / 1e6f;
```

这样测到的是"GPU 执行这帧实际花了多少时间"，而不是"CPU 等待刷新用了多久"。
