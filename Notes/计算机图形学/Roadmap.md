# Graphics Journey 路线图

> 本路线与 [[Notes/SelfGameEngine/0_RoadMap|SelfGameEngine 构建手册]] **深度融合**。你的图形学知识不再是一条孤立的"理论线"，而是直接服务于引擎构建的"能力线"。
>
> **核心原则**：不在图形学里闭关修炼，而是在关键节点**切入引擎开发**，用工程需求反向驱动深度学习。
>
> **构建哲学**：先建立像素级直觉（软渲染器），再理解GPU如何替代你的for循环，最后把这些知识组织成引擎的渲染管线。
>
> **主线脊柱**：阶段三及以后的所有阶段，只回答一个问题——**像素需要的信息从哪里来？** 单 Pass 世界里，信息只来自顶点与常量；当像素需要读"别的像素、别的视角、上一帧"，就进入了多 Pass 世界。整个后半段路线就是这场"单 Pass → 多 Pass"的世界观升级。
>
> **维护说明**：2026-07-25 重构——阶段三及以后重写为"两幕脊线"结构：幕一·单Pass世界（阶段三~五）→ 幕二·多Pass世界（阶段六~十一）→ 幕三·组织与性能（阶段十二~十四）→ 幕四·扩展菜单（阶段十五~十七）。旧结构下阶段三及以后的全部笔记已删除，按新结构重新产出；阶段一、二保持不动。所有目录结构、文件名、阶段划分、依赖关系以本文件为唯一权威。

### 关键认知：这不是"先学后做"

传统思路：先花3个月把图形学学完，再开始写引擎渲染。

**本路线的思路**：
- 阶段一：建立像素级直觉（帧缓冲是什么），并在CPU上实现软渲染器（3D数学 + 光栅化 + 深度缓冲）。
- 阶段二：建立完整概念地图，理解GPU并行架构，并让GPU画出第一个三角形；进一步加载一个外部 OBJ 模型作为阶段二综合实践。
- 阶段二后：**切入引擎阶段1.2**——你有足够知识把"最简图形后端"从清屏升级到画三角形。
- 幕一（阶段三~五）：单 Pass 世界——像素的信息只来自顶点数据与常量参数。每阶段学完立刻切引擎对应模块（材质系统、资源管线、渲染队列）。
- 幕二（阶段六~十一）：多 Pass 世界——后处理、阴影、延迟渲染、SSAO 看起来是不同技术，本质全是同一句话："像素要读已经算好的像素"。必须在引擎代码里边做边学。
- 幕三（阶段十二~十四）：不再是"学图形学"，而是"在引擎里设计渲染架构"，并建立"测量→定位→优化"的性能方法论。
- 幕四（阶段十五~十七）：全部**按需深入**——专题是菜单不是顺序，光追是概念储备，AI 渲染是扩展阶段。

**里程碑**：理解像素在内存中的表示，建立"3D世界 = 模型 + 材质 + 光源 + 相机"的直觉；并能在CPU上从零实现一个软渲染器——画线、填充三角形、做3D变换、投影到屏幕、处理深度。

## 阶段二：从软光栅到 GPU 流水线

**里程碑**：能说清楚"我写的软渲染器 `for(y) for(x)` 循环"在 GPU 上被哪些机制替代，并能让 GPU 画出第一个彩色三角形。

> **问题驱动**：两块半透明玻璃叠在一起，先画谁结果完全不同。不透明物体靠深度测试乱序画都对，透明为什么不行？
>
> **与已有知识的衔接**：深度缓冲（[[Notes/计算机图形学/软光栅化与3D数学/3D光栅化与深度缓冲|阶段一]]）解决的是"谁挡住谁"，但它假设像素是不透明的——透明打破了这个假设。
>
> **下一步**：排序能解决"正确性"，但解决不了"浪费"——大量像素被后面的物体盖住，片段着色器白算了。

### 5.2 深度预Pass与Early-Z

- [ ] [[Notes/计算机图形学/透明与混合/深度预Pass与Early-Z|深度预Pass 与 Early-Z]] — Early-Z 硬件机制、先画一遍"只写深度"的快速 Pass、overdraw 的量化、深度预 Pass 顺带简化透明排序

> **问题驱动**：复杂场景里 overdraw 可能是 3~5 倍——每个像素被反复着色再被覆盖。能不能先廉价地铺好深度，让正式绘制时被挡像素直接丢弃？
>
> **与 SelfGameEngine 的关系**：深度预 Pass 是引擎渲染队列排序（`5.6 渲染队列与DrawCall组织`）的重要 Phase 拆分依据。
>
> **下一步**：排序 + 预 Pass 能应付玻璃，但粒子和头发是成千上万层交错——CPU 排序既慢又排不对（三角形级交错怎么办）？

### 5.3 顺序无关透明 OIT

- [ ] [[Notes/计算机图形学/透明与混合/顺序无关透明OIT|顺序无关透明 OIT]] — 为什么排序在三角形交错时无解、Depth Peeling 的多 Pass 剥离、Weighted Blended OIT 的单 Pass 近似、各自的显存与精度代价

> **问题驱动**：两团烟互相穿插，任何全局排序都是错的。能不能不排序也得到"看起来正确"的透明？
>
> **与 SelfGameEngine 的关系**：引擎 `5.20 基础粒子系统` 选择混合策略时的决策依据。
>
> **本阶段增量**：透明不再是"玄学 bug 高发区"——你知道每种方案在牺牲什么。更重要的是：Depth Peeling 已经需要"把中间结果存下来再读"——单 Pass 世界的边界到了。
>
> **下一步**：进入幕二。像素需要的信息不再只来自顶点和常量，而是来自"别的像素、别的视角"——这一切的总开关，是先把画面画到一张能读的"画布"上。

---

## 幕二 · 多 Pass 世界（阶段六~十一）

> **这一幕回答的问题**：像素需要的信息，来自**别的像素**（后处理）、**别的视角**（阴影）、**别的 Pass 存下的几何**（延迟渲染、SSAO）、**上一帧**（TAA）。幕二的所有技术都是同一句话的变种：**"像素要读已经算好的像素"**。
>
> 总开关是"画到纹理"（阶段六）；其余每个阶段都是这个总开关的一种用法。学幕二时始终问自己：这个 Pass 读什么、写什么、谁在前谁在后。

---

## 阶段六：画到画布上（离屏渲染与 FBO）

**里程碑**：理解"渲染到纹理"的本质——把中间像素结果存成可读数据。这是多 Pass 世界的总开关：后处理、阴影、延迟渲染、屏幕空间技术，全部建立在这一个能力之上。

> **与 SelfGameEngine 的关系**：离屏渲染目标就是引擎 `5.18 后处理栈架构` 和 RenderTarget 管理的基础。理解"画到纹理" = 理解引擎为什么需要 RenderTarget 抽象。

**验收标准（能看见的）**：
- [ ] 能解释"为什么后处理不能在一个 Pass 里完成"（当前管线只能写不能读）
- [ ] 能理解"渲染到纹理"的本质：把中间像素结果存成可读数据
- [ ] 能用 OpenGL 创建 FBO，将场景渲染到纹理再显示到屏幕
- [ ] 能说清颜色附件/深度附件各自存什么、谁消费它们
- [ ] 能自由切换"直接渲染"和"渲染到 FBO 再处理"

### 6.1 离屏渲染与FBO

- [ ] [[Notes/计算机图形学/离屏渲染/离屏渲染与FBO|离屏渲染与FBO]] — 默认帧缓冲为什么只写不读、"画到纹理"的信息结构、颜色附件/深度附件、纹理附件与渲染缓冲的取舍、完整性检查

> **问题驱动**：阶段五的 OIT 需要"把中间结果存下来再读"；模糊效果需要"读到已经算好的相邻像素"。但当前管线是单向的：顶点 → 光栅化 → 逐像素计算 → 写入画面。怎么让画面变成"可读的"？
>
> **与已有知识的衔接**：阶段四里纹理是"图片作为输入"；本模块是它的逆命题——"画面作为输出，存成纹理"。输入和输出打通了，多 Pass 世界的大门就开了。
>
> **下一步**：FBO 用多了，各种坑开始出现。

### 6.2 FBO常见陷阱

- [ ] [[Notes/计算机图形学/离屏渲染/FBO常见陷阱|FBO常见陷阱]] — 完整性检查、附件尺寸匹配、状态切换开销、调试技巧

> **本阶段增量**：你掌握了多 Pass 世界的总开关——任何"先画到画布上再加工"的技术，对你都不再神秘。
>
> **下一步**：第一个严肃的多 Pass 应用——把最终画面当输入，对它再加工：后处理。但两段效果一串起来，画面总是"脏脏的"——问题可能不在算法，在色彩空间。

## 阶段七：加工最终画面（后处理与色彩空间）

**里程碑**：建立"线性色彩空间"的正确认知——这是一切多 Pass 叠加的正确性地基；掌握后处理管线的信息流动（每个 Pass 读什么、写什么）；并学会消费深度纹理——这是"深度图如何应用"的第一站。

> **与 SelfGameEngine 的关系**：本阶段和引擎 `5.18 后处理栈架构`、`5.19 后处理效果算法` **完全一一对应**。建议直接以"在引擎里实现后处理"为目标来学习本阶段。

**验收标准（能看见的）**：
- [ ] 能解释 Gamma 校正前后，同一段光照代码为什么结果不同；知道纹理、Shader、显示器各自在哪个色彩空间工作
- [ ] 能用全屏四边形组织多 Pass 后处理链，说清每个 Pass 读什么、写什么
- [ ] 能实现可分离双 Pass 高斯模糊，并解释为什么比单 Pass N×N 卷积更快
- [ ] 能实现 Bloom：提取亮部 → 模糊 → 叠加回原图
- [ ] 能把深度纹理可视化成灰度图，并把非线性深度值还原成线性视距
- [ ] 能解释 FXAA 为什么"便宜但糊"，TAA 为什么"清晰但复杂"

### 7.1 色彩空间、Gamma 与线性渲染

- [ ] [[Notes/计算机图形学/后处理/色彩空间Gamma与线性渲染|色彩空间、Gamma 与线性渲染]] — 显示器的非线性响应、sRGB 纹理、光照为什么必须在线性空间计算、渲染管线的 Gamma 校正链路

> **问题驱动**：两张 50% 灰的半透明图叠在一起，为什么不是预期的亮度？在 sRGB 纹理上直接做光照，结果为什么总是发脏？
>
> **与后续阶段的关系**：线性渲染是 Bloom（7.4）、HDR（[[Notes/计算机图形学/Roadmap#阶段九：让像素物理可信（PBR）|阶段九]]）和一切多 Pass 叠加的正确性前提。在进入后处理之前先把地基打正。
>
> **下一步**：色彩空间理顺了，正式组织多 Pass 后处理。

### 7.2 后处理管线

- [ ] [[Notes/计算机图形学/后处理/后处理管线|后处理管线]] — 全屏四边形、后处理Shader、多Pass结构、RenderTarget切换

> **问题驱动**：一个Pass只能输出到一个目标，但模糊需要先水平再垂直。怎么组织多个Pass？
>
> **与 SelfGameEngine 的关系**：这就是引擎"后处理栈"的最小实现。
>
> **下一步**：具体实现一个后处理效果——高斯模糊。

### 7.3 高斯模糊

- [ ] [[Notes/计算机图形学/后处理/高斯模糊|高斯模糊]] — 卷积核、可分离模糊、双Pass优化、性能对比

> **问题驱动**：直接做N×N卷积，每像素要采样N²次。怎么优化到2N次？
>
> **与 SelfGameEngine 的关系**：高斯模糊是引擎后处理系统的"Hello World"。实现它 = 验证整个后处理管线通路。
>
> **下一步**：高斯模糊会了，但"亮部向外溢光"的效果不是模糊全屏——怎么只模糊亮部再叠回去？

### 7.4 Bloom 泛光

- [ ] [[Notes/计算机图形学/后处理/Bloom泛光|Bloom 泛光]] — 亮度阈值提取、Mip 链逐级下采样模糊、渐进上采样叠加、与线性色彩空间的关系

> **问题驱动**：全屏模糊让一切都糊，但 Bloom 只要"亮的地方发光"。怎么把亮部单独拿出来处理？
>
> **与 SelfGameEngine 的关系**：对应引擎 `5.19 后处理效果算法` 的 Bloom（Downsample/Upsample Mipchain）。
>
> **下一步**：FBO 的深度附件一直在默默工作——它存着"每个像素的深度"。如果能读到它，能做什么？

### 7.5 深度纹理的读取与应用

- [ ] [[Notes/计算机图形学/后处理/深度纹理的读取与应用|深度纹理的读取与应用]] — 深度值可视化、非线性深度到线性视距的还原、软粒子（粒子被前景柔和遮挡）、屏幕空间雾、景深（DOF）入门

> **问题驱动**：粒子穿帮地切过地面、远处物体该隐入雾中——这些效果都需要"知道这个像素离相机多远"。深度纹理就是答案，但它的值不是线性的，怎么还原成可用的距离？
>
> **与后续阶段的关系**：这是"深度图如何应用"的第一站。[[Notes/计算机图形学/Roadmap#阶段八：光会被挡住（阴影）|阶段八]]的阴影映射本质是"从光源视角生产的深度纹理"；[[Notes/计算机图形学/Roadmap#阶段十一：直接光之外（屏幕空间技术与全局光照）|阶段十一]]的 SSAO/SSR 是深度+法线的更高级消费。
>
> **下一步**：后处理链越来越长，画面边缘的锯齿却还在——能不能把"抗锯齿"也当成一个后处理？

### 7.6 屏幕空间抗锯齿

- [ ] [[Notes/计算机图形学/后处理/屏幕空间抗锯齿|屏幕空间抗锯齿]] — FXAA 的边缘检测模糊、SMAA 的形态学改进、TAA 的时间维度复用概念、与 MSAA 的取舍

> **问题驱动**：MSAA 贵，且和[[Notes/计算机图形学/Roadmap#阶段十：一百个灯（多光源与延迟渲染）|阶段十]]的延迟渲染天生冲突。能不能在最终图像上做抗锯齿，一个 Pass 搞定？
>
> **与后续阶段的关系**：TAA 的完整展开（含历史帧重建、超分辨率）在[[Notes/计算机图形学/Roadmap#阶段十四：能画了，快吗（性能分析与帧优化）|阶段十四]]。
>
> **本阶段增量**：引擎能进行离屏渲染和后处理，从"直接画"升级到"先画再处理"；并且懂得了色彩空间和深度纹理这两个"隐形地基"。
>
> **下一步**：到目前为止，光照都是"无条件照亮"——光有遮挡才有体积感。像素怎么知道"它看不看得见光源"？答案藏在刚学会的技能里：从光源的视角，也画一遍深度。

## 阶段八：光会被挡住（阴影）

**里程碑**：方向光与点光源阴影落地。理解阴影映射的本质 = **从光源视角生产的深度纹理**——阶段六"画到纹理"与阶段一"深度缓冲"的第一次严肃组合，多 Pass 世界的第一个"为光照服务"的应用。

> **与 SelfGameEngine 的关系**：阴影 Pass 是引擎 `5.7 RenderGraph与多Pass资源管理` 中的新增节点——它是你第一个"为光照服务的多 Pass 系统"，正好检验 RenderGraph 的依赖表达能力。

**验收标准（能看见的）**：
- [ ] 能画出 Shadow Map 的两 Pass 结构：光源视角深度 Pass + 主相机比较 Pass
- [ ] 能解释 shadow acne 和 peter-panning 为什么是一个 bias 的两端
- [ ] 能用 PCF 把硬阴影边缘柔化，并解释均匀 PCF 为什么会糊
- [ ] 能解释 CSM 为什么把视锥分段，以及分割处接缝怎么消
- [ ] 能实现点光源的 Cube Shadow Map
- [ ] 引擎中能开关方向光阴影，画面体积感明显提升

### 8.1 阴影映射基础

- [ ] [[Notes/计算机图形学/阴影/阴影映射基础|阴影映射基础]] — Shadow Map 两 Pass 算法、光空间矩阵、bias、shadow acne 与 peter-panning、PCF 入门

> **问题驱动**：光有遮挡才有体积感。怎么让片段知道"它能不能看见光源"？先让光源"看"一遍场景（存深度），主 Pass 再逐像素比较。
>
> **与已有知识的衔接**：这就是[[Notes/计算机图形学/Roadmap#阶段七：加工最终画面（后处理与色彩空间）|阶段七]]深度纹理应用的第二站——深度测试本身是固定硬件，但"把深度存成纹理再消费"是 Shader 与多 Pass 编排的典型模式。
>
> **下一步**：基础链路通了，但阴影边缘锯齿 + 硬得像刀切。怎么柔化？

> **问题驱动**：真实阴影在半影区是渐变的（光源有面积），Shadow Map 比较是二值的。怎么从"二值"走向"渐变"？
>
> **下一步**：一张 2048 阴影图覆盖整个开放世界，近处精度全废。怎么办？

- [ ] [[Notes/计算机图形学/阴影/级联阴影CSM实战|级联阴影 CSM 实战]] — 视锥分割策略、每级联一张阴影图、级联间过渡与接缝消除、级联数量与显存的取舍

> **问题驱动**：透视相机近处 1 米和远处 1 公里共用一张阴影图，texel 密度天差地别。按距离分档为什么能大幅改善？
>

- [ ] [[Notes/计算机图形学/阴影/点光源阴影|点光源阴影]] — Cube Shadow Map 六面渲染、双抛物面近似、多光源阴影的图集管理

> **问题驱动**：一个方向光一张阴影图；一个灯泡照亮整个房间，需要朝六个方向各画一次。怎么组织？

## 阶段九：让像素物理可信（PBR）

**里程碑**：金属/粗糙度 PBR 材质 + IBL 环境光照 + HDR 全链路打通。画面从"塑料感"升级为"材质可信"——同一件资产在任何光照环境下都表现一致。

> **与 SelfGameEngine 的关系**：PBR 材质定义 = 引擎 `5.11 材质系统架构` 的"高级材质"支持；IBL 的辐照度图/预滤波图是资产管线的新产物。

**验收标准（能看见的）**：
- [ ] 实现金属/粗糙度 PBR 材质（至少支持 Albedo+Normal+Metallic+Roughness）
- [ ] 能解释能量守恒为什么让 PBR 在任何光源下都不"穿帮"
- [ ] 能实现 IBL：漫反射辐照度图 + 镜面预滤波环境图 + BRDF LUT
- [ ] 整个渲染链在线性 HDR 空间计算，最后经 ACES 色调映射输出
- [ ] 能说清金属粗糙度模型覆盖不了哪些材质（清漆/布料/SSS/各向异性）

### 9.1 PBR基础

- [ ] [[Notes/计算机图形学/基于物理的渲染/PBR基础|PBR基础]] — 微表面模型、Cook-Torrance BRDF、金属/粗糙度工作流、能量守恒、简化 GLSL 实现

> **与已有知识的衔接**：你在[[Notes/计算机图形学/Roadmap#阶段三：让像素响应光（直接光照与数据流）|阶段三]]学过 Blinn-Phong 的局限（参数不直观、能量不守恒）。PBR 就是解决这些问题的方案。
>
> **与 SelfGameEngine 的关系**：PBR 材质定义 = 引擎材质系统的"高级材质"支持。
>
> **下一步**：直接光再准，没有环境光的金属就是一团黑——怎么把"整个天空"变成光源？

### 9.2 IBL 基于图像的环境光照

- [ ] [[Notes/计算机图形学/基于物理的渲染/IBL基于图像的环境光照|IBL 基于图像的环境光照]] — 环境光为什么是"半球积分"、辐照度图（漫反射）、按粗糙度预滤波的环境图（镜面）、BRDF 积分 LUT、split-sum 近似

> **问题驱动**：BRDF 能算"一个光源打过来"，但现实里物体被整个环境照亮。环境光是无限多个方向光的积分——实时算不动，能不能预处理成纹理查表？
>
> **前置依赖**：[[Notes/计算机图形学/纹理系统/Cubemap与纹理数组|Cubemap 与纹理数组]]（4.7）。
>

**里程碑**：不再是"学图形学"，而是"在引擎里设计渲染架构"。理解为什么需要把"画什么"和"怎么画"分开，搭建最小 RHI 抽象层，并理解 RenderGraph、剔除、GPU-Driven 这些现代引擎骨架。

> **问题驱动**：顶点着色器输入必须是顶点、片元着色器输入必须是像素——但我想并行算的是"10 万个粒子的新位置"，跟管线的固定阶段都对不上。GPU 能不能给我一块"裸的并行算力"？

### 13.2 GPU 粒子模拟与渲染

### 硬依赖规则（不可跳过）

1. `阶段一` → **所有后续阶段**（建立像素直觉起点）
2. `阶段二` → **所有 GPU 相关阶段**（软渲染器到 GPU 的概念地图是一切的前提）
3. `阶段三`（光照 + 数据通道）→ `纹理映射与UV坐标`（4.1）：先会用数据流实现基础光照，再学用纹理替代纯色
4. `多重纹理与材质`（4.5）→ `离屏渲染与FBO`（6.1）：先会纹理当输入，再会纹理当输出
5. `色彩空间、Gamma 与线性渲染`（7.1）→ `Bloom 泛光`（7.4）、`HDR与色调映射`（9.3）：线性空间是一切多 Pass 叠加的正确性前提
6. `离屏渲染与FBO`（6.1）→ 阶段八（阴影）、阶段十（延迟渲染）：它们都是"画到纹理"的消费者
7. `Cubemap 与纹理数组`（4.7）→ `点光源阴影`（8.4）、`IBL 基于图像的环境光照`（9.2）
8. 阶段三 + 阶段四 → `阶段九`：光照模型 + 多纹理材质是 PBR 的直接前置
9. `深度纹理的读取与应用`（7.5）+ `延迟渲染与G-Buffer`（10.1）→ `阶段十一`：SSAO/SSR 依赖深度+法线缓冲
10. 幕二（阶段六~十一）→ `阶段十二`：先手工管理过多 Pass 的失控，才懂 RenderGraph 在解决什么
11. `GPU 的并行执行模型`（2.3）→ `阶段十三`：Compute Shader 是并行模型的直接编程接口
12. 幕一 + 幕二 → `阶段十五`：专题是已有积木的组合应用，不引入新概念
13. `阶段十二` + `阶段九` → `阶段十七`：AI 渲染建立在传统管线基础之上
14. `阶段八` + `阶段十一` → `阶段十六`：先懂光栅的阴影/GI 近似，才懂光追在替换什么
15. `阶段七` → `阶段十四`：性能分析可在阶段七之后任意时间切入

## 如何避免沉迷图形学？

> 这是本路线最重要的设计约束。

### 红线规则

| 规则 | 说明 |
|------|------|
| **阶段二后不闭关** | 完成从 OBJ 文件到第一个模型后，必须回探引擎阶段1.2（把清屏升级为画三角形），并接入 5.8~5.10 资源链路。不准"我再学学纹理再切入" |
| **阶段三后必须切** | 完成"让像素响应光"后，必须开始参与引擎 5.11~5.14 材质系统的开发。此时你已对数据通道、数据频率、光照在管线中的位置有基础理解 |
| **阶段四后必须切** | 完成纹理系统后，必须正式参与引擎 5.9/5.10 资源加载与热重载的开发 |
| **幕二在引擎里学** | FBO/后处理/阴影/PBR/延迟渲染/GI 必须在引擎代码里边做边学。不要在独立Demo里写三遍 |
| **概念级模块不动手** | 11.4、12.8、阶段十六为概念导览，读懂即可，**禁止**为此写大型 Demo |
| **专题菜单不抢跑** | 阶段十五必须完成阶段九后按需选学；一次一个专题，且落地为引擎能力 |
| **没有数据不优化** | 阶段十四之前不谈性能优化；任何优化必须先有 profiler 数据支撑 |
| **阶段十七不抢跑** | AI 渲染（3DGS/NTC/神经降噪）必须在阶段十二（渲染架构）和阶段九（PBR）之后系统切入 |

### "沉迷"的预警信号

如果你发现自己：
- 在独立Demo里实现了5种不同的高斯模糊优化，但引擎里还没有后处理管线 → **停止！回引擎！**
- 为了"完整理解"Vulkan，花两周写了一个能清屏的Vulkan程序，但引擎的RHI还是空的 → **停止！用OpenGL先跑通引擎！**
- 读了10篇PBR论文，但引擎里连一个带纹理的立方体都跑不起来 → **停止！先让立方体跑起来！**
- 收藏了50个Shadertoy效果想"全部学会"，但引擎的材质系统还是空的 → **停止！一次一个效果，且必须落进引擎！**

### 正确的并行节奏

```
周1-2：    阶段二（GPU 流水线：第一个三角形 + OBJ 模型）
周3：      回探引擎阶段1.2 → 把最简图形后端从清屏升级到画三角形
```
