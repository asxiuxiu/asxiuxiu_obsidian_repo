# 法线变换的几何直觉

## 问题 0：一个被压扁的球，光照为什么全错了？

你在 [[Notes/计算机图形学/Shader与光照/GPU上的Blinn-Phong光照|光照在管线中的位置]] 里已经在片段着色器里算了光照。代码大致长这样：

```glsl
vNormal = mat3(transpose(inverse(uModel))) * aNormal;
```

为什么这里要套一个 `transpose(inverse(...))`？为什么不能直接写：

```glsl
// ❌ 错误：非均匀缩放会让法线变形
vNormal = mat3(uModel) * aNormal;
```

---

## 问题 1：法线是"方向"，不是"位置"

模型矩阵 `uModel` 通常包含：

- **平移**：改变位置
- **旋转**：改变朝向
- **缩放**：改变大小

法线是方向向量，没有"位置"。平移对法线没有意义——把模型移到世界坐标 (10, 0, 0)，它的朝向不会因此改变。

所以法线变换只需要 Model 矩阵的 3×3 旋转/缩放部分，不需要平移。这就是为什么代码里用 `mat3(uModel)`。

但即便如此，直接乘还是会在**非均匀缩放**时出错。

---

## 问题 2：非均匀缩放为什么破坏法线？

想象一个圆球被压扁成椭球：

- **x 方向放大 2 倍**
- **y 方向压扁到 0.5 倍**

球面上某一点的切线方向也会跟着变形：x 方向的切线被拉宽，y 方向的切线被压扁。法线必须始终垂直于切线。如果法线和切线用同一个矩阵变换，它就不再垂直于新的切线了。

**直觉**：非均匀缩放把空间"拉歪"了。切线被拉向一个方向，法线需要被"推回"相反的方向，才能继续保持垂直。

---

## 问题 3：法线矩阵是什么？

正确的法线变换是：

$$
\mathbf{M}_{normal} = (\mathbf{M}_{model}^{-1})^T
$$

读作：模型矩阵的**逆**，再**转置**。最后取左上 3×3 部分。

```glsl
vNormal = mat3(transpose(inverse(uModel))) * aNormal;
```

### 为什么是这个公式？

- **逆**撤销了缩放的"拉伸"效果：x 放大 2 倍，逆矩阵就把 x 缩小 0.5 倍。
- **转置**把方向重新对齐到新的切线空间。

合在一起，法线矩阵让法线在新的、被拉歪的空间里仍然垂直于表面。

### 特殊情况

- 只做**旋转**：Model 矩阵的 3×3 部分就是正交矩阵，它的逆等于转置，所以 `transpose(inverse(M)) = M`。此时直接乘 Model 也对。
- 做**均匀缩放**：缩放因子会约掉，直接乘 Model 的 3×3 部分结果方向正确（长度会变，但通常会在片段着色器里 `normalize`）。
- 做**非均匀缩放**：必须用法线矩阵。

> 所以为了保险，always 用 `transpose(inverse(model))`。只有在明确知道只有旋转且性能极度敏感时，才可以优化掉。

## 问题 4：工业引擎通常怎么做？

在 Shader 里调用 `inverse()` 不是免费的：

- 顶点着色器每个顶点都要算一次。
- 对于 10 万个顶点的模型，这是重复计算。
- 现代 GPU 有求逆指令，但仍然有开销。

工业引擎的标准做法：**在 CPU 端算好法线矩阵，作为 Uniform 传进来**。

```cpp
// CPU 端（C++）
glm::mat3 normalMatrix = glm::transpose(glm::inverse(glm::mat3(model)));
glUniformMatrix3fv(normalMatrixLoc, 1, GL_FALSE, glm::value_ptr(normalMatrix));
```

```glsl
// GPU 端（GLSL）
uniform mat3 uNormalMatrix;
vNormal = uNormalMatrix * aNormal;
```

这样 GPU 每个顶点只做一次矩阵-向量乘法，而不是一次矩阵求逆。

---

## 问题 5：法线变换和管线位置的关系

法线变换发生在**顶点着色器**，因为：

1. 顶点法线是每个顶点的 Attribute。
2. 光照在片段着色器里算，需要世界空间法线。
3. 所以顶点着色器负责把法线从模型空间变换到世界空间，然后插值给片段着色器。

```
模型空间法线 aNormal
        │
        │ 顶点着色器：mat3(transpose(inverse(uModel))) * aNormal
        ▼
世界空间法线 vNormal
        │
        │ 光栅化器插值
        ▼
片段着色器收到插值后的 vNormal，normalize 后用于光照
```

## 常见陷阱

| 陷阱 | 错误写法 | 后果 |
|------|---------|------|
| 直接用 Model 矩阵乘 | `mat3(uModel) * aNormal` | 非均匀缩放后法线不再垂直表面，光照方向歪 |
| 忘记 normalize | `dot(vNormal, lightDir)` | 插值后法线长度变短，点乘结果偏小，光照变暗 |
| 在 CPU 端算好却传错 | 把 4×4 model 当 normalMatrix 传 | 类型不匹配，数据错位 |
| 只旋转时过度优化 | 到处写死 `mat3(uModel)` | 一旦加入缩放就出 bug |

## 设计 checklist

| 检查项 | 标准 |
|--------|------|
| 法线变换位置 | 顶点着色器 |
| 法线矩阵 | `transpose(inverse(model))` 的 3×3 部分 |
| 性能敏感场景 | CPU 端算好法线矩阵，作为 Uniform 传入 |
| 片段着色器 | 必须 `normalize(vNormal)` 后再做点乘 |
| 缩放类型 | 非均匀缩放必须用法线矩阵；纯旋转可直接用 model 的 3×3 部分 |
