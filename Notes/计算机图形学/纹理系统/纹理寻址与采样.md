# 纹理寻址与采样

## 问题 0：你一直在偷懒——之前所有例子都假设 UV 落在 [0,1] 里面

回头看阶段四的前三篇笔记，所有例子——砖墙贴到平面上、人脸贴到球面上、地面延伸向远方——都有一个你没意识到的隐藏前提：**UV 落在 [0,1] 区间之内**。在这个区间内，UV 平滑映射到表的每一格，查表逻辑干净利落。

但一个场景里只有少数表面的 UV 被美术乖乖限制在 [0,1] 里。以下是三件每天都在发生、UV 必然出界的事：

1. **地面要铺满整个场景**。美术给的是一块 2m×2m 的石板纹理，但地面有 2000m×2000m。每个顶点 UV 只覆盖 2m×2m 的范围——剩下的 1998m 怎么办？让美术把 UV 展开到整张 2000m 的表吗？那是天文数字的浪费。
2. **角色皮肤的 UV 确实被美术精心安排在 [0,1] 内**——但浮点数不精确。UV 插值过程中，某个像素算出来是 0.999999 还是 1.000001，你控制不了。如果这个微小的"出界"让查表逻辑崩溃，边缘像素就会错色。
3. **阴影深度图**里存的不是颜色，是"离光源有多远"。光源视角下，只有 [0,1] 范围内的物体在阴影图上有记录——范围之外，深度图里没有有效数据。如果主相机视角的某个像素对过去发现 UV 超出了光源的 [0,1]，它该认为"这里能看见光源"还是"这里被挡住了"？答案取决于你的选择，但**默认行为肯定是错的**。

每种出界场景需要的处理方式完全不同。这不是一个"设个参数就完"的琐碎配置——是**同一个数据通道（查表机制）面对不同表面类型时，需要外挂一个独立的"出界规则"**。

---

## 问题 1：最 naive 的方案——出界就是出界，不查了

如果 UV 出界就返回一个固定颜色（比如黑色），地面会怎样？

```
地面上，UV 覆盖 2m×2m 的区域。
2m 以外的顶点 → UV 超出 [0,1] → 黑色。
结果：场景里 2m×2m 之内是石板，之外是纯黑。
```

这显然不行——地面需要覆盖整个场景。但让我们停一下：这个"黑色"的选择，反过来暴露了寻址模式的真正本质。

> **本质问题：当 UV 指向表的外面，该返回什么？这个问题的答案不是"选个好看的参数"，而是取决于"表的外面是什么"——不同的表面类型，表的外面是不同的东西。**

石板地面：表的外面还是石板。你往左走一步，看到的石板花纹和 UV=1.0 那侧连在一起——地面是周期性重复的。角色皮肤：表的外面是"皮肤的终结"。脸部纹理到脖子就结束了，脖子以下不是"又一张脸"——皮肤不重复。深度图：表的外面是"没有任何物体的空白"。没有物体挡住光——外面应该是亮的（或是暗的，取决于你的阴影策略），但绝不是"又一块深度图"。

这三种"外面"对应了三种完全不同的出界规则。下面逐个走。

---

## 问题 2：地面——表的外面"还是这个表面"（重复平铺）

回到 2000m×2000m 的地面。你手上有一块 1024×1024 的石板表，UV 从 (0,0) 铺到 (1,1) 覆盖 2m×2m。地面顶点上，美术只需给 UV 覆盖前 2m，剩下 1998m 的顶点——UV 直接给 1000.0 就行。

但 UV=1000.0 要怎么查表？表的宽度是 1（归一化的 UV 空间），1000 = 1.0 × 1000。你需要的无外乎是：**把 UV 当周期信号，每过一个 1 就回到起点。**

```
数学：出界 UV → 只看小数部分
  UV = 3.7  →  frac(3.7) = 0.7  → 查 UV=0.7 的格子
  UV = -1.2 → 也取小数（不同实现处理方式略有差异，但思想一致）

像素效果：
  (0,0)─(1,0)─(2,0)─(3,0)  ← 屏幕上的几个相邻砖块
   表      表      表      表    ← 每个都是同一张表，"缝"对着"缝"
```

这就是**重复（Repeat）模式**。数学就是取小数部分。一个更直觉的描述是：假设表的左边界和右边界是连在一起的，上边界和下边界也是连在一起的——整张表被贴在了一个无限大的平面上，相邻的"副本"之间花纹自然衔接。

### 为什么这是默认行为

这里有一个反直觉的事实：Repeat 是几乎所有图形后端的**默认**寻址模式。但大多数纹理的 UV 是被美术限制在 [0,1] 之内的——理论上永远不该出界。为什么默认选了一个"出界才触发"的模式？

原因不是地面铺贴的需求——那只是受益者之一。真正的原因是：**UV 插值永远不可能精确停在 1.0 上。** 浮点计算 + 透视校正插值 + 光栅化的离散化 = 边缘像素的 UV 可能是 1.00001 或 -0.00001。如果默认是"出界就崩"的模式，每张贴图每条边都是潜在的渲染 bug。

而 Repeat 的"出界取小数"，恰好让这种微小的越界**静默地正确**：UV=1.00001 被当成 0.00001 处理，接缝两边的表值完美连续——因为 Repeat 本来就是设计成"边界相连"的。Repeat 是默认，不是因为"大家都要平铺"，而是因为**浮点误差天然需要边界连续性，而 Repeat 恰好免费提供了这种连续性**。

### Repeat 的坏处：当你不需要边界连续时反而会坏事

但这正是所有 bug 的源头：某个纹理不需要重复（比如角色皮肤、UI 图标），UV 确实被控制在 [0,1] 内，但某个边缘像素的 UV 越界了 0.00001——Repeat 沉默地把它映射到了表的另一侧——最左边和最右边的颜色通常完全不同（皮肤的左边是耳朵，右边是脖子），于是出现一条肉眼可见的"反射线"：

```
屏幕上的角色脸部边缘：
  最后一列像素的 UV = 1.00001
  Repeat 把它映射到 UV = 0.00001 → 查到了皮肤的另一侧边缘（耳朵的颜色）
  结果：一道与周围格格不入的细线贴在边缘上

这就是 classic 的 edge bleeding——它不是"出了 bug"，
而是 Repeat 的"边界连续性"在你不想要连续性时变成了伤害。
```

这个 bug 是纹理系统里最隐蔽的 one-liner 杀手之一——它不报错、不影响帧率、只会让角色边缘多一道色线。修复方法就是下一篇要讲的：关掉 Repeat，换成 Clamp。

## 问题 3：皮肤——表的外面"还是边缘这个颜色"（边界钳制）

对于 UV 被限制在 [0,1] 内的纹理（角色、道具、UI），你需要的是相反的规则：**出界了别去找表另一侧的格子，就停在边界上，把边界的颜色拉出去填满外面。**

```
UV < 0   → 当 0 处理（表的左/下边界）
UV > 1   → 当 1 处理（表的右/上边界）

像素效果：纹理贴完一遍就停了，外面的像素全是边界格子的颜色。
```

这就是**钳制到边缘（Clamp to Edge）**。它消灭了 edge bleeding：UV=1.00001 被钳制为 1.0，查到的还是表最右边那列格子的颜色——和相邻像素一致，细线消失。代价是 UV 真的大幅出界时（比如某个顶点 UV 给了 3.0），外面铺满的是边界颜色——不是黑色、不是错误、就是边界的颜色被"拉满"。对于一张配好边缘颜色的皮肤贴图，这正好就是你要的。

### 一个微妙的正确性条件

Clamp to Edge 的正确性依赖一个前提：**表的四个边界上，格子的颜色要能代表"表的外面"**——也就是，边界周围不能有明显的颜色突变。

如果皮肤贴图的最后一行是脖子的肉色，但脖子下面本该是衣服——Clamp to Edge 会把肉色拉下去，脖子以下全是肉色。这不美，但比 Repeat 把耳朵颜色反射到脖子旁边强得多。根本的解决方式是**美术在画表时就留好边缘**——让边界格子是过渡色或纯色，拉出去也不违和。这在 UI 贴图、Sprite 精灵图里尤其重要。

## 问题 4：镜像——表的外面是"镜子里倒过来的表"

在某些场景下，你希望纹理是周期性的，但不是"缝对缝"——而是"每过一次边界就翻一次面"。典型场景是水面波纹：同样一组波形重复出现，但相邻的两个周期应该是镜像对称的（波峰对波谷，而不是波峰对波峰），否则接缝处会出现一个突兀的方向跳变。

```
UV 的整数部分：
  偶数（0,2,4...）→ 正常查表（frac(UV)）
  奇数（1,3,5...）→ 翻转查表（1 - frac(UV)）

像素效果：
  [0,1] 正常 → [1,2] 镜像 → [2,3] 正常 → [3,4] 镜像 ...
  相邻周期在边界处纹理方向连续——没有"方向跳变"。
```

这就是**镜像重复（Mirrored Repeat）**。它不像 Repeat 和 Clamp to Edge 那样高频出现，镜像重复也不顺带解决浮点误差问题（因为它对 [0,1] 边界的行为和 Repeat 一样）。它的存在理由很专一：**当纹理本身不是旋转对称的（有方向性），你又需要它无缝平铺，镜像能消除相邻周期之间的方向跳变。** 代价是平铺出来的效果是"来回翻面"，如果纹理有文字、logo 这种明显的方向标志，镜像平铺会非常奇怪——这种纹理只能用 Repeat。

## 问题 5：深度图——表的外面是"一个我指定的常数"（边界纯色）

前面三种模式有一个共同的隐蔽假设：**表的外面总归是表本身的某种延续**——或是平铺复制、或是边缘拉伸、或是镜像翻转。它们都对"有意义的表面"管用。

但在深度图、阴影图这类"~={green}表里存的是测量值而非颜色=~"的场景，这个假设不成立。

### 回顾：阴影深度图里存的是什么

[[Notes/计算机图形学/Roadmap#阶段八：光会被挡住（阴影）|阶段八（阴影）]] 会详细展开，但这里只需要一个轮廓感受：阴影映射的本质是，先把相机放到光源位置"看"一遍场景——这次看到的不是颜色，而是~={green}"光源视角下每个像素离光源有多远"——存进一张深度表=~。然后主相机渲染时，每个像素先算出"在光源深度表里的 UV 位置"，查到光源视角下的深度，比较"该点的深度"和"表中记录的深度"——如果该点深度更大，说明有东西挡在它前面，这个像素就在阴影里。

问题来了：主相机能看到的东西，光源不一定能看到。场景里有个物体在光源的照射范围之外——它的 UV 投影到光源深度表上时，**UV 超出 [0,1]**。此时 Repeat 会把它映射到深度表另一侧——光源视角下另一个物体的深度，完全无关。Clamp to Edge 会取边界——光源能照到的最远处——也是错的。

**这里需要的规则完全不同：表的外面不是一个"表面"，而是一个"纯色常数"——我决定它是几，它就是几。** 对于阴影深度图，这个常数通常设为 1.0（最远的可能深度，或者更精确地：一个明确表示"这里没被挡"的值）。任何 UV 出界，直接返回这个常数，不碰表本身。

这就是**钳制到边框（Clamp to Border）**。它和 Clamp to Edge 的区别只在"外面那个颜色从哪来"：Clamp to Edge 从边界格子取，Clamp to Border 从一个专门指定的纯色取。

### 它不可替代的场景

| 场景         | 表里存什么    | Repeat 的问题       | Clamp to Edge 的问题 | Clamp to Border 的价值    |
| ---------- | -------- | ---------------- | ----------------- | ---------------------- |
| 阴影深度图      | 深度值      | 把不相干深度映射进来，产生假阴影 | 边界深度不一定是"没遮挡"的语义  | 指定 1.0 = "这里没东西挡光"     |
| 天空盒边缘      | 天空颜色     | 天空不该重复           | 可行，但不如纯色干净        | 用纯黑或纯白补边框，然后 blend     |
| 数据表（ID 贴图） | 物体 ID 编码 | 不相干的 ID 被错误引用    | 边界 ID 被错误赋予       | 用 -1（无效 ID）明确标记"无归属"   |
| 投影贴花       | 贴花图像     | 不该平铺的贴花多了一排排     | 可行，边界色会拉出去        | 用透明色（alpha=0）消灭出界区域的贴花 |

共性规律：**当表里存的不是颜色——而是深度、ID、编码——"平均"和"复制"都失去了物理意义，只有"常数"有语义。** 这和 Mipmap 篇"金字塔依赖表里是颜色"是同一条规则的另一种露面。

## 问题 6：Wrap 模式与 UV 精度——两个看起来无关、实则合谋的坑

Wrap 模式本身没讲完。还有一个深层的坑藏在使用模式和数据精度的交集里，等到你实现多纹理材质（4.5）时会跳出来。

**问题：每种 Wrap 模式对 UV 的"小数部分"怎么解释，边界条件不一致。**

- Repeat：`frac(x)`。精确到采样位置的 UV 微元。
- Clamp to Edge：钳制到 [0,1]。边界上的半个纹素（比如双线性过滤需要读 UV 两侧的格子时，钳制使"界外"的格子不可得，等价于只能读界内格子——边界纹素被"拉满"）。
- Mirrored Repeat：`abs(frac(x + 1) * 2 - 1)` 或等价变换，边界处的梯度是 Reverse 方向的。

这三种模式在浮点精度的边界下表现不一致。但最重要的是记住一个结论：**Wrap 模式的选择会影响过滤的效果——特别是双线性过滤在纹理边界处**。当你用双线性 + Repeat，边界两边的纹素混得好好的；改用 Clamp to Edge，边界纹素不再混入对侧纹素，而是被边界的纹素自己反复参与混合——边界颜色会轻微"偏色"。这不是 bug，是两种"表的外面"定义的自然结果。

这在不同 wrap 设为 UV 两个方向独立控制的场景尤其值得留意——水平 Repeat + 垂直 Clamp to Edge 是很常见的组合（比如天空穹顶的水平方向要平铺、垂直方向要停住），但边界混合的不对称会让某些双线性查询结果轻微偏色。工程上这几乎感觉不到，但知道它能省掉一次困惑。

## 收尾落地：寻址模式在各图形后端中怎么表达

> 推导到此结束——你已经知道：寻址模式的本质是回答"表的外面是什么"，四种模式是四种不同的答案；"表数据"和"查表方式"（过滤 + 寻址）是两个独立决策，同一张地面表可以切换 Repeat/Clamp 而不重新加载数据。下面是各后端的落地，纯文字、无代码，具体实现交给 AI 生成。

- **OpenGL**：寻址模式是纹理对象上的一个参数，U、V（以及 3D 纹理的 W）三个方向独立设置。默认是 Repeat——这使得浮点误差天然安全，也使得"忘了关 Repeat"成为最常见的纹理 bug。后来引入的独立采样器对象允许把过滤 + 寻址从纹理数据上剥离出来——同一张表皮可以用一个 Repeat 采样器和一个 Clamp 采样器分别读，不用创建两份数据。但 OpenGL 的 Clamp to Border 有两个重要限制：边框颜色在部分嵌入式平台（OpenGL ES 部分版本）不可用；它一度被标记为 deprecated（后来恢复），所以在跨平台项目里不如 Clamp to Edge 那么"安全无痛"。
- **Vulkan**：寻址模式是采样器对象里的三个独立参数（addressModeU / V / W），与纹理图像完全分离。这也是 4.2 那套"数据与查法分离"规律的本色出演：`VkImage` 只管数据，`VkSampler` 只管查法（过滤 + 寻址 + 各向异性 + LOD 偏置），你创建几套采样器、配给哪些图像，是完全自由的。Vulkan 同样默认 Repeat。Clamp to Border 需要额外设置一个 borderColor，且部分硬件对自定义颜色的支持有限——查询设备特性是标配操作。
- **D3D12**：与 Vulkan 同路——寻址模式是静态采样器或独立采样器描述符上的字段，独立于纹理 SRV。默认同样是 Repeat。边框颜色选项在 D3D12 中更丰富（支持透明黑和不透明黑），但仍需检查硬件特性。
- **Metal**：`MTLSamplerDescriptor` 的 `sAddressMode` / `tAddressMode` 字段，采样器与纹理分离。两个值得注意的差异：Metal 的默认是 Clamp to Edge 而不是 Repeat（这是最激进的默认差异——Metal 的设计哲学是"如果你 UV 在 [0,1] 内就不要冒险平铺"）；Metal 提供 Clamp to Zero（直接返回透明黑，不用设置边框颜色）作为 Clamp to Border 的轻量替代，在不支持边框颜色的硬件上也能用。

一句话对照：**所有现代 API 都把寻址模式视为采样器（查表方式）的一部分，与纹理数据本身完全解耦。** OpenGL 传统上把它粘在纹理对象上（和过滤参数一样），但后来的扩展甚至新 API 的设计都在向"解耦"收敛——Metal 的默认值差异是一个警醒：**不要假设默认行为跨平台一致**，寻址模式应该是引擎材质系统里显式管理的一个参数，而不是靠"反正默认是 Repeat"混过去。

## 总结：这篇笔记建立的核心认知

1. **寻址模式的本质不是"参数选项"，是四种不同的"表的外面是什么"的假设**：Repeat = 外面还是这表面（周期性连续）；Clamp to Edge = 外面是边界颜色（出界就停）；Mirrored Repeat = 外面是倒过来的表面（消方向跳变）；Clamp to Border = 外面是一个常数（数据不是颜色时的语义兜底）。

2. **Repeat 是默认，但默认不等于"最好是 Repeat"**——Repeat 真正解决的日常问题是浮点误差导致的微小越界；它之所以被选为默认，不是因为它"最常用"，而是因为它让最细微的精度问题也静默正确。代价是"不该重复的纹理被静默重复了"，edge bleeding 是 loading 问题发生最频繁的一个 bug。

3. **Clamp to Edge 是"UV 被控制在 [0,1]"的标准搭配**：消灭 edge bleeding，代价是 UV 出界时的视觉效果取决于边界格子的颜色——需要美术配合。

4. **Clamp to Border 只有一种场景下不可替代：表里存的不是颜色**。深度图、ID 贴图、投影贴花——"表的外面"在这些场景下没有物理意义，需要用一个语义明确的常数（1.0 表示没遮挡、-1 表示无归属、0 表示透明）来填。

5. **寻址模式 = "查表方式"四个维度中的最后一个**：过滤（怎么取值）→ 选层（查哪一层）→ 层间（层号是小数怎么办）→ **寻址（UV 出界怎么办）**。四个维度全部独立于表数据——这是 4.1 提出"数据与查法可分"之后的第三次正面回收。引擎材质系统设计时，"一套采样器对象 + 多张纹理" vs "每个纹理粘一套采样参数"，本质上就是这四个维度要不要和表数据绑定的选择。
