# 顺序无关透明 OIT

## 开场：排序走到头了——两团互相穿插的烟

先把前两篇的成果复习一遍，确认你手里的工具：

- **5.1 排序**：透明物体从远到近画，一遍画完。玻璃窗、桌边几块小玻璃——画得又对又便宜。
- **5.2 深度预 Pass**：正式绘制前先把不透明深度铺好，被挡住的像素在着色之前就被 Early-Z 扔掉。overdraw 下来了，帧率回来了。

现在往场景里丢两团烟雾粒子，让它们互相穿插。画面立刻变回"乱码级"：一团烟忽前忽后、边缘闪烁、某些角度甚至像被挖了洞。

为什么？回顾 5.1 的结论：正确的混合要求"从远到近"，而排序排的是**物体**。可烟雾是成千上万个小四边形，两团烟的粒子在空间里完全交错——**某个像素上，可能 B 的 5 个粒子在前、A 的 3 个粒子在前，还全按各自的深度交错排列**。没有任何"按物体"的排序能让这种像素得到正确顺序，因为正确答案本来就是"像素级"的。

更糟的是，**单个物体自己就能制造这种交错**——玻璃杯里插根吸管，杯壁的三角形和吸管的三角形在像素上互相穿插。物体内部的三角形顺序是建模时就定死的，排序改不了它。

> 核心矛盾升级：**排序要的是"物体之间能分出先后"，而正确混合要的是"像素上逐层分出先后"。** 前者给不了后者——越高精度的排序越贵，而精确到像素的排序根本不存在（CPU 没法给上百万个像素逐个排层）。所以必须换思路：**不排序，直接在像素上解决"这里叠了好几层怎么办"。**

这整类不排序的透明方案，有个统一的名字——**OIT（Order-Independent Transparency，顺序无关透明）**。名字直白：**结果与绘制顺序无关**。接下来看两条最重要的实现路线。

但先钉死最关键的一个洞见：**"不排序"不等于"放弃顺序"**。正确混合依然需要每层的前后关系，只是~={green}这套关系不再由"先画谁"来提供，而是由"每层真实的深度"来提供=~。这句话是理解全篇的门。

## 问题 1：要做到"不排序也画对"，最少需要知道什么？——每个像素一份"层清单"

先把目标钉死。回顾 5.1 的混合方程，看它面对一堆透明层时，到底是怎么一步一步算的。假设一个像素上叠着三层（从远到近：背景 B → 红玻璃 C₂ → 蓝玻璃 C₁），按 5.1 的规则从远到近逐步混合：

```
第 1 步：画背景           画布 = B
第 2 步：画红玻璃        画布 = a₂×C₂ + (1−a₂)×B
第 3 步：画蓝玻璃        画布 = a₁×C₁ + (1−a₁)×[ a₂×C₂ + (1−a₂)×B ]
```

把最后一行拆开：

```
最终 = a₁×C₁  +  (1−a₁)×a₂×C₂  +  (1−a₁)×(1−a₂)×B
```

念出来就是一条规律——每一项都是"某个颜色 × 一串份额"：

- **C₁（最近这层）**最终被看见多少：`a₁` × 前面没有别的层挡它，全量留下；
- **C₂**最终被看见多少：先被 C₁"放过"了 `(1−a₁)`，再乘自己留下的 `a₂`；
- **背景 B**最终被看见多少：被 C₁ 放过 `(1−a₁)`，又被 C₂ 放过 `(1−a₂)`。

这里的 `(1−a)` 就叫**透射率**——这层"放行了多少光"（1 减去不透明度，就是它有多透）。于是上面的规律可以换一种更物理的说法：

> **每一层最终被看见多少 = 自己留下的份额 × 前面所有层依次放过它的份额。**

站在某一层往回看：你要看见它后面的东西，光必须先穿过它前面（更靠近相机的）每一层——每层拿走一份、放行一份，最后到你眼前的光，已经被前面所有层"透射"了一遍。这就是"前面所有层透射下来的光"这句话的意思。它和我们熟知的混合方程是同一件事的两种说法：一个是"把两个颜色按比例合在一起"，一个是"光穿过层层薄纱，每层拿走自己那一份"。

注意"前面"两个字——**顺序就藏在这里**：谁在"前面"，取决于这层在光路里的真实深度，不取决于先画谁。

好，有了这条规律，"画对透明"需要的全部信息就清楚了。对**每一个像素**，只要知道三件事：

1. 这个像素被哪些层覆盖？（每一层的颜色、不透明度）
2. 这些层从近到远怎么排？（每一层的深度）
3. 背景看去是什么颜色？

这三件事合起来，就是这份像素的**层清单**。有了它，从远到近把 5.1 的混合方程过一遍——精确结果，100% 对。

> 核心转折：5.1 的排序是在**绘制前**（CPU 上）猜"哪层在前"，猜的依据是物体中心——精度天然不足。OIT 家族换了个做法：**不在绘制前猜，而在像素上现场收集**——每画一层，就把这一层记到它覆盖的像素那里；一帧画完，每个像素手里都攒了一份自己的层清单（哪怕只是个近似），再统一处理。

难点立刻显现：**一个像素要同时记住多层信息，而像素的"信箱"只有一个通道。** 怎么把多层塞进一个像素？两条路由此分岔：

- **路 A：一遍一遍地画，每遍只取"下一层"**——用层数换精确（深度剥离）。
- **路 B：根本不存层，只存"累积量"**——把层层传递的递归抹平，用与顺序无关的求和替代（加权平均）。

先走 A。

## 问题 2：一遍一遍地画，每遍剥掉最前面一层——深度剥离（Depth Peeling）

先钉死两个看着很像、其实说的是两回事的词：

- **"层"**：某个像素上、沿视线方向堆叠的透明片。把相机当眼睛，往一个像素射一束光，光路上每一个透明片元就是"一层"。两团烟在某像素上压了 5 个片元，就是 5 层。**层是"像素身上的东西"，是我们要处理的原料。**
- **"Pass"**：渲染器从头到尾跑完整一遍绘制命令——从顶点到片元到测试到写颜色。**Pass 是"我们动手的手段"。**

⚠️ 这里的"Pass"，和你上一篇（5.2 深度预 Pass）里看到的"三个 Pass"不是一回事。5.2 的三个 Pass 分工**不同**：深度 Pass 只写深度、不透明 Pass 画不透明、透明 Pass 画透明——各自干各自的活。而深度剥离的一串 Pass **干的都是同一件事**——每一遍都只剥一层透明。一个是"不同类型的工作挨个排"，一个是"同一件事反反复复做 N 遍"。别把两种"多批次"搞混，这是理解本节的第一道坎。

接下来是深度剥离的核心动作，一句话：**每一遍绘制（一个 Pass），只取"当前所有透明层里最前面那一层"。**

为什么做得到？因为深度测试的天职就是"谁近谁赢"——不加任何门槛的第一遍，最前层本来就是深度测试的自然胜利者。真正的技术点在第一遍之后：**第二遍怎么保证只拿第二层、不碰第一层？** 办法是把第一遍剥出的深度当成**门槛**——凡是深度比这个门槛还近（或相等）的片段全部弃掉，剩下的片段里再做普通深度测试，取最前面那个。剥几层，就设几次门槛；每次的门槛，都来自上一遍剥出的结果。

用夹心糖的例子走一遍（贴着相机那端，是糖纸、糖衣、糖心三层）：

```
第 1 遍：不加门槛，普通深度测试 → 糖纸过（最前层）
第 2 遍：门槛 = 糖纸的深度，比糖纸更近的全弃掉 → 糖衣变成"剩下的最前层"，过
第 3 遍：门槛 = 糖衣的深度，比糖衣更近的全弃掉 → 糖心过

每一遍的"过"只发生在自己那一遍：
第二遍画的时候，糖纸已经被门槛挡掉了，所以同一个像素、同一片几何，
每一遍都能剥出不同的一层，不会重复拿。
```

```
第 1 遍：普通绘制，深度测试拿最前层 → 记下深度 d₁ 和颜色
第 2 遍：弃掉所有深度 ≤ d₁ 的片段，剩下的取最前 → 第二层，记下 d₂
第 3 遍：弃掉所有深度 ≤ d₂ 的片段，剩下的取最前 → 第三层，记下 d₃
……
第 k 遍：弃掉所有深度 ≤ d₍ₖ₋₁₎ 的片段，取最前 → 第 k 层
当某一遍没有任何片段通过 → 所有层剥完，结束

每剥出一层，先把这层（颜色+深度）存下来
全部剥完后，把各层从远到近依次混合进最终颜色
（剥取顺序是前→后，倒过来用就是远→近）
```

这里有个**双循环**要建立起来（很多人卡在这一段，就是因为只看到"循环"，没看到"嵌套"）：

- **外层循环：剥几层（Pass 数）**。这一帧某个像素有几层，就得剥几遍——3 层剥 3 遍，10 层剥 10 遍。
- **内层循环：每剥一层，都要把场景里所有透明几何重新画一遍**。第 1 遍画全部粒子、第 2 遍还是画全部粒子、第 3 遍依然——只是每一遍设的门槛不同，筛掉的层不同。

所以"画 N 遍"和"剥 N 层"是同一件事的一体两面：**外层数 = 层数，内层每遍都跑完整几何。** 10 层透明 = 10 个外层 × 每一遍里全部粒子的几何处理——深度剥离的贵，贵在这句话：它不是"多画一点点"，是"整个透明场景原样画 N 遍"。

和 5.2 的深度预 Pass 一比，恰好**完全反过来**：

| | 多花的代价 | 买到的收益 |
|---|---|---|
| **5.2 深度预 Pass** | 多跑一遍"半价"绘制（只写深度、不着色） | 正式绘制时 Early-Z 挡掉大部分像素着色——**花小钱，省大钱** |
| **深度剥离** | 每一遍都是"全价"绘制（完整几何 + 着色），场景画 N 遍 | 逐像素 100% 精确——**纯加钱，为正确性付费** |

这套方案诚实地说一说代价：

| 收获 | 付出的代价 |
|---|---|
| **逐像素精确**：每个像素的层序由其真实深度决定，混合结果 100% 正确——这是"排序"永远给不了的 | **Pass 数量 = 最深的层数**：场景有 10 层透明叠加就要画 10 遍，每遍都重跑一遍全部几何处理 |
| 无"贪心猜测"，结果可复现 | 每一层都要存下一张"剥离结果"（深度+颜色），显存随层数线性增长 |
| 硬性上限可预测（层数固定时开销固定） | 层数不定（粒子成千上万层时）开销爆炸，只能靠硬性截断，截断处出现穿帮 |

两个实用的工程改进（了解即可）：一是**先画一遍查一查**——某遍结束时统计通过片段数，为零就提前结束循环，避免为不存在的高层数白跑；二是**双深度剥离（Dual Depth Peeling）**——同一遍里从前面剥一层、从后面剥一层（前后各设一个门槛），层数减半；更激进的还有一次剥多层的变种。但这些都改变不了一个事实：**深度剥离的正确性按层数线性收费，层一多，账单就付不起。**

## 问题 3：能不能不逐层，一遍算出个"差不多对"？——加权平均（Weighted Blended OIT）

粒子、头发这种场景，层数可能上百甚至上千，深度剥离直接破产。能不能牺牲一点精确性，把代价压成常量？

先从问题 1 的展开式看看"顺序"到底藏在哪——顺便看清它**没**藏在哪：

```
最终 = a₁×C₁  +  (1−a₁)×a₂×C₂  +  (1−a₁)×(1−a₂)×B
```

先别急着叫它"递归"，把它当一张**分账明细表**看：右边已经是三项相加，每一项是"某一层（或背景）自己那点光，最终被看见多少"。重新摆一摆，每项都是同一个形状——`自己的份额 × 一串放行数`：

```
最终 = (a₁×C₁) × 1                   ← C₁ 前面没层挡它，放行串是空串（=1）
     + (a₂×C₂) × (1−a₁)              ← C₂ 的光还要穿过 C₁，被放行 (1−a₁)
     + (B)     × (1−a₁)×(1−a₂)       ← 背景的光要穿过 C₁ 和 C₂ 两张网
```

这个形状里藏着两个数学事实，是后面一切的地基：

- **事实一：乘法不认先后。** `(1−a₁)×(1−a₂)` 和 `(1−a₂)×(1−a₁)` 结果一模一样。用纱网想最直观：每层透明都是一张纱网，`(1−a)` 是它的透光度。光穿过一叠纱，总放行率就是把每张的透光度乘起来——**先穿哪张、后穿哪张，完全不影响**。所以"背景那束光被放过多少"本身，根本不依赖顺序。
- **事实二：这张表能拆成互不相欠的独立项。** 每一项只由"某一层的颜色"和"别人的放行数"相乘构成，没有哪一项是"前一项的结果"再加工的。递归那种"后一步的原料是前一步的成品"的接力感，只是运算过程的表象，不是结构的本质；结构的本质是——**最终颜色 = 各层独立贡献之和**。

那"混合必须排队算"又是什么？顺序的真身只剩一处：**`(a₂×C₂)` 乘的偏偏是 `(1−a₁)`**——"这份光更近的网是哪几张、各自多浓"这份选择，才是顺序的藏身处。要精确回答它，就得把层从近到远排好、照着递归一步步算——那是深度剥离的路。

WBOIT 的赌注就一句话：~={green}**别数"前面是哪几张网"，按"这张网离眼睛多远"直接估一个数顶替=~。**（这个数就是**深度权重**，怎么设、为什么是近似，下一段展开。）于是每层再也不用等别人、自己就能报数，像素上允许的运算只剩两类——**往 `C`、`W` 里加，往 `T` 里乘**。恰好，加法和乘法都不挑先后：

> 一个像素先遇到哪层、后遇到哪层，最终结果都一样——**这就是"顺序无关"的全部含义：像素身上只有加法和乘法，没有别的。**

OIT 家族的第二条路——**加权平均（Weighted Blended OIT，WBOIT）**——就这样一句话压掉所有排序：

```
第 1 遍（累积）——每层把自己的颜色"折算成三个数"交到像素手里：
  颜色累积  C += (这层的颜色 × 不透明度) × 深度权重
  权重累积  W += 不透明度 × 深度权重
  透射累积  T ×= (1 − 不透明度)              ← 近似，用来淡化后面的背景
  画完，每个像素只剩这 3 个数字——不管下面叠了 5 层还是 5000 层

第 2 遍（合成）——全屏画一个大矩形：
  平均颜色 = C / W
  最终颜色 = 背景颜色 × T + 平均颜色
  → 完成，总共 2 个 Pass，层数多少都一样
```

光说"加法和乘法不挑先后"还不够，拿两层在像素里撞见的先后顺序实际验一遍。设远处一层蓝烟（颜色 (0,0,1)、α=0.2、深度权重 0.8），近处一层红烟（颜色 (1,0,0)、α=0.3、深度权重 0.5）：

```
先画红、后画蓝： C = (1,0,0)×0.3×0.5 + (0,0,1)×0.2×0.8 = (0.15, 0, 0.16)
先画蓝、后画红： C = (0,0,1)×0.2×0.8 + (1,0,0)×0.3×0.5 = (0.15, 0, 0.16)  // 一模一样

W = 0.3×0.5 + 0.2×0.8 = 0.31（谁先谁后都一样）
T = (1−0.3)×(1−0.2) = 0.56（谁先谁后都一样）
```

为什么能这样？因为**每一项都是"这一层的颜色 × 这一层的权重"，只跟自己有关**——它不消费"前一层算出来的中间结果"，自然也不用等前人。真正的混合规则里那种"谁乘在谁的前面"（`(1−a₁)×a₂`）的配对，在 WBOIT 里被深度权重顶替掉了；剩下的 C、W 只有加法、T 只有乘法，**像素最后手里那 3 个数，跟层被撞见的先后无关**——画完这一遍，再把它们拿去合成，就是最终颜色。

关键细节是**深度权重**：给远近不同的层不同的权重——近的权重高、远的权重低。为什么？因为真实视觉里，近处的烟雾本来就该看得更清楚、在画面里占更大份额。注意：这是**启发式**（合理定性拍板，不是物理推导）——这正是它和深度剥离的本质区别：一个用"近似"换"固定开销"，一个用"全价 N 遍"换"逐像素精确"。

对比一下两条路的信息结构：

```
深度剥离（精确）      加权平均（近似）

每个像素记 N 层         每个像素记 3 个数
（深度+颜色）×N 张图   （颜色累积、权重累积、透射累积）×1 组
N 个 Pass               2 个 Pass
层越多越贵              恒定为 2 个 Pass
结果完全正确            结果是"视觉上的近似"
```

代价必须说清楚：

- **颜色会被"平均"**：两团一红一蓝的浓烟叠在一起，如果权重压不住，会混出一团"紫雾"——真实世界里近的那团应该完胜，但平均近似做不到"完胜"。
- **不透明度越高，误差越大**：α 接近 1 时，混合本质是"覆盖"，平均天然打不过覆盖。
- **带太强的画面要求（比如近处高光）会明显失真**。
- 好消息是：**粒子、烟雾、尘埃、光晕这类"模糊材质"恰恰是最不敏感的**——它们本身就千层万层、颜色过渡柔和，WBOIT 的误差几乎不可见，而它们的层数恰恰是深度剥离付不起的。这正是工业界把 WBOIT 和粒子系统绑定的原因。

> 中间地带：如果既想要"固定 Pass"，又想要精确一些，还有**分层加权（Hybrid Transparency）**：把视锥按深度切成几段，段内在层数少的地方做精确排序、层多的地方回落加权。概念了解即可——它再次印证：**这一家族全是"精确度 ÷ 成本"的滑块，没有免费的午餐。**

## 问题 4：所以到底用哪种？——一张决策表

阶段五的透明工具现在齐了，把三条路线放一起对账（表格只做总结，每条都已在前文展开）：

| 方案             | 正确性             | 性能                | 显存     | 适用                         |
| -------------- | --------------- | ----------------- | ------ | -------------------------- |
| **排序**（5.1）    | 物体不交错时正确        | 1 个 Pass + CPU 排序 | 无      | 玻璃窗、少量不交错透明体——仍然是**默认首选**  |
| **深度剥离**       | **逐像素 100% 正确** | Pass 数 = 最大层数     | 每层一张图  | 层数可控又要求绝对正确（多层玻璃、透明 UI 前景） |
| **加权平均 WBOIT** | 视觉近似（近处权重）      | **恒定 2 个 Pass**   | 两三张累积图 | 粒子、烟雾、尘埃、光晕——大量低敏感材质       |

**决策规则就一句**：层数少、不交错 → 排序白拿；层数多、材质糊 → 加权平均白拿；层数可控又较真 → 深度剥离按需付费。没有一条是银弹，但也不再需要"排序玄学"。

## 落点：日常场景都是混合的——一个房间加一团烟

上表容易让人以为"整帧只用一个方案"，实际游戏从来不是这样：**大部分场景大部分时候是"没多少透明"的，偶尔冒出一团烟、一层雾、一连串粒子。** 更常见的一点是——**每种透明各管各的像素**：玻璃管玻璃、烟管烟，同一帧里它们绝大部分时候根本不叠在同一个像素。所以严格答案：**方案是"按物体分类"选的，不是"按整帧"选的**。但在一团烟雾真正穿过一扇玻璃窗的那一小撮像素上，你确实会遇到跨类叠加，这要在设计管线时就想好。

### 不透明场景里的一团烟：最简单，先别想复杂

一个几乎全是不透明的房间，中间飘一团烟。真实做法朴素到可能让你意外——**把烟按透明物体正常画上去（5.1 排序），不透明物体不参与它的排序**：

```
1. 画不透明：正常画（房间、家具全画完，深度写进缓冲）
2. 画透明：开启深度测试但关闭深度写入，把烟从远到近排好画上去
   —— 烟只跟"已经画好的房间"混合，房间的深度提前把它挡得严严实实
```

这其实**就是 5.2 干的事**，也是前面说"排序（5.1）仍是默认首选"的原因：烟和一屋子不透明物体彼此**不交错**（不透明物体之间也没有多层的语义），排序只发生在烟自己的层内部。唯一注意点：关闭深度写入后，**前后两团烟之间要自己排好**（如果有多团），房间永远挡得住它们。

### 一堆不同材质的透明混在一起：按类别分桶，全都要读它的像素信息

更常见也更自由的做法是**透明队列分桶**——引擎把整个帧的透明体按照"各自的像素要求"拆成几趟（桶之间天然不互相交错，因为它们的像素不重叠）：

| 桶 | 画几趟 / 用什么 | 例子 |
|---|---|---|
| **不透明** | 1 趟 | 房间、家具——照常画 |
| **简单透明**（层少、不交错） | 1 趟排序画 | 玻璃窗、水杯 |
| **粒子 / 烟雾 / 半透明贴花** | 1 趟 WBOIT | 烟、火、雾、尘埃 |
| **精确透明**（层多且需要过硬的深度） | N 趟深度剥离，或排序 + 提前截断 | 爆炸核心、多层玻璃 UI |

顺序一般是：不透明先画（供深度和背景）→ 简单透明 → WBOIT 粒子 → 精确透明收尾。**一个像素最多只属于某一个桶**——普通的像素走"房间+玻璃"的排序路径，烟（在另一批像素上）走 WBOIT 路径，互不相干；只有极少数"烟恰好盖在玻璃上"的像素，管线的设计才需要额外考虑（这时通常会放弃在那一小撮像素上的完美正确，接受近似——**近乎所有游戏都为此妥协**）。

### 为什么实际管线的方案组合永远是"混合"而不是"一个万能大法"

1. **没有任何方案是"免费"的**：WBOIT 的误差只在"模糊材质"上不可见；深度剥离的 Pass 数上限必须靠截断压住；排序是最省的那条。
2. **帧里各部分的要求天生不同**：一扇要求精确透射的玻璃幕墙，和千层万层的火焰，在同一个渲染器里默认走不同的路径。
3. 一个"每帧都能画全部类型"的管线，在真实游戏里要做的，通常只是**预先规划几个透明桶 + 摊好它们的先后顺序**；剩下百分之九十九的像素，仍然是普通的不透明写入。

一句话收尾：**"一团烟在一个普通房间"这种场景，就是透明家族里最基础、最常见的用例——排序（5.1）单遍处理就够；WBOIT 与深度剥离，是当透明开始大量出现、且互相纠缠（粒子、玻璃套玻璃）时才升级选择的工具。**

## 问题 5：区别不在"是不是多个 Pass"——而在"中间结果里装的是什么"

先把这一个说法纠正过来：**5.2 的深度预 Pass 确实不只是一个 Pass，也确实把前面算出的结果存下来、供后面的 Pass 读回去用。** 所以习惯上那句"OIT 是第一次越过单 Pass 世界"是**错的**——深度模型早就越过了。那 OIT 和 5.2 是不是就没区别了？有，但区别不在"存不存中间结果"，而在**中间结果里装的是什么数据**：

| | 存的"中间结果" | 装的是什么 | 用途 |
|---|---|---|---|
| **5.2 深度预 Pass** | 深度缓冲 | 每个像素"最近的图元的深度"——一个**距离数字**，不是画面颜色 | 遮挡判定（Early-Z 剔除） |
| **OIT（深度剥离 / 加权平均）** | 每层剥离结果 / 累积的 C·W·T | **颜色画面本身**——最终要写上屏幕的那些颜色值，只是还没最终合成 | 作为"下一步要读的画面数据" |

一个关键的区分：**深度缓冲里装的数据，本身不是画面。** 它是"远近关系"这种辅助信息，只服务于"谁遮谁"的判断；它不记录颜色，不能当成图像去看、去加工、去美化。而 OIT 的中间结果——剥离出的那层颜色、累积出的 C·W·T——**就是画面本来的颜色值**，只是把它们从"最终结果"降级成了"中间产物"：先画一遍，把颜色算出来存进一块可读的缓冲，下一步绘制再把它读回来当输入、继续加工。

所以正确的说法不是"OIT 越过了单 Pass 世界"（**单 Pass 在 5.2 就已经不存在了**），而是：

> **OIT 第一次让"画面颜色本身"变成了可读回传的中间产物。** "多 Pass + 中间结果回读"这套能力，在 5.2 的深度上就出现了；OIT 把同一套能力用到了画面数据上。

这才是通往幕二的那道门：~={green}从这一刻起，"把一张画面画到一块能读的缓冲上、再作为输入参与后续绘制"成了核心动作。后处理读的"已经画好的画面"、阴影读的"从光源视角做的深度"、延迟渲染读的"别的 Pass 攒下的几何"——全是这个动作的延伸=~。OIT 是第一个把画面数据当中间产物来读的技术，它在幕一的压轴出场，正好把通往下一幕的门闩拉开了。

> 一句话：**"把画面颜色变成可读可传的中间产物"——这个能力，才是幕一与幕二的分水岭。** 深度自 5.2 起就是可读的中间产物了，OIT 进了一步：**颜色画面**也是了。

## 落地表达：这套思路在渲染器里怎么组织

推导到这里，方案已经清晰：**要么逐层剥（正确性按层数收费），要么加权累积（正确性按近似打折）——共同前提是把中间结果存下来再读。** 看各后端怎么表达这个前提。

**"把中间结果存下来再读"这个能力，各后端都有专门抽象**：

- **OpenGL** 用一个"离屏渲染目标"对象表达"画到一块不上屏的画布"——画完这张画布本身就可以当纹理读回来。一个对象包办"画到哪"和"怎么读"。
- **Vulkan / D3D12 / Metal** 把同一件事拆得更显式：Vulkan 拆成"渲染过程描述"（这一遍读什么、写什么、读写先后）和"具体图像绑定"（画到哪张图）两件事——因为它要在录制命令前就把读写关系固定下来，驱动才能做完整验证。
- 这些抽象的机制细节、坑和最佳实践，是**阶段六（画到画布上）** 的主题——本笔记只需记住结论：**OIT 已经亲手用到了"可读画布"，下一幕的每项技术都会再用它。**

**排序与 OIT 的组织位置**：深度剥离与加权平均都发生在引擎的渲染队列里——前者是"对透明队列循环执行多次剥离子队列"，后者是"透明队列只执行两次（累积 + 合成）"。自研引擎的[[Notes/SelfGameEngine/渲染管线与画面/基础粒子系统|基础粒子系统]]在选择烟雾/粒子的混合策略时，正是用这张决策表：粒子默认加权平均，特殊镜头（要求精确遮挡的爆炸核心）回退深度剥离。

## 明确推荐：一张决策清单

1. **默认还是排序**（5.1）——零额外开销，能处理日常玻璃与单层粒子；只有它明显出错时才升级。
2. **粒子、烟雾、尘埃、光晕 → 加权平均（WBOIT）**：恒定 2 个 Pass，与层数无关，对"模糊材质"的近似误差肉眼不可见。
3. **层数可控且要求逐像素正确（多层玻璃、透明前景 UI）→ 深度剥离**：提前设定最大层数，落地为显存和 Pass 预算，超过的部分用截断接受穿帮。
4. **实现顺序建议**：先做排序（验证管线正确），再加加权平均（覆盖粒子主战场），深度剥离作为按需增强——每层抽象都不要破坏前一层，因为它们在真实引擎里共存。
5. **记住分水岭**：无论选哪条，都依赖"把画面颜色变成可读的中间产物"这个能力——它就是下一幕的总开关，也是阶段六的主角。
