# 顺序无关透明 OIT

## 开场：两团烟互相穿插，这场戏怎么排？

前两篇把透明推到了"工程可用的水平"：排序负责正确性（5.1），深度预 Pass 负责性能（5.2）。一个室内场景的不透明墙面 + 几块玻璃窗，已经能画得很好了。

然后你往场景里丢了一团烟雾粒子，又丢了一团，两团粒子互相穿插。画面立刻变回"乱码级"：一团烟忽前忽后，边缘闪烁，某些角度甚至像被挖了洞。

问题在哪？回顾 5.1 的结论：正确混合要求"从远到近"，排序排的是**物体**。可烟雾粒子是成千上万个小四边形，两团烟的粒子在空间里完全交错——**A 的前半部分粒子在 B 前面，B 的后半部分粒子又在 A 前面**。没有任何"按物体"的排序能在这种交错里正确，因为正确答案本来就是"像素级的"：某个像素上，可能 B 的 5 个粒子在前、A 的 3 个粒子在前，还全按各自的深度交错排列。

更糟的是，**单个物体自己就能制造这种交错**——玻璃杯里插一根吸管，杯壁的三角形和吸管的三角形在像素上互相穿插，一个物体内部的三角形顺序是固定死的（建模时就定死了），排序改不了它。

> 核心矛盾升级：**排序要的是"物体之间可分出先后"，而正确混合要的是"像素上逐层分出先后"。** 前者给不了后者——越高精度的排序越贵，而精确到像素的排序根本不存在（CPU 无法逐像素排序上百万层）。必须换思路：**不排序，直接解决"每个像素上有多层怎么办"。**

这整类不排序的透明方案，有个统一的名字——**顺序无关透明（OIT，Order-Independent Transparency）**。名字直白：结果与绘制顺序无关。接下来看两条最重要的实现路线。

---

## 问题 1：正确混合到底需要什么信息？——每个像素的一份"层清单"

先把目标钉死。回到 5.1 的混合方程：最终颜色 = 按深度从远到近，把每一层依次混进来。对一个像素来说，完美的透明渲染只需要一样东西：**这个像素覆盖了哪些透明层，每层的深度、颜色、不透明度。** 有了这份"层清单"，从远到近过一遍方程，结果就是精确的。

排序方案的问题在于：它试图在**绘制前**（CPU 上）把"哪层在前"猜出来，而猜的依据是物体中心——精度天然不足。

OIT 家族换个角度：**不在绘制前排序，而在像素上现场收集。** 每画一层，就把这层的信息"记"到它覆盖的像素那里；一帧画完，每个像素手里都攒了一份自己的层清单（哪怕只有个近似），然后再统一处理。

这个思路的难点立刻显现：**一个像素要同时保存多层信息，而像素的"信箱"只有一个通道。** 怎么把多层塞进一个像素？两条路由此分岔：

- **路 A：一遍一遍地画，每遍只取"下一层"**——层数换来精确（深度剥离）。
- **路 B：不存层，只存"累积量"**——把混合的递归性抹平，用与顺序无关的求和替代（加权平均）。

先走 A。

---

## 问题 2：一遍一遍画，每遍剥掉一层——深度剥离（Depth Peeling）

想象一个洋葱：你要拿到"第 k 层"的皮，前提是前 k−1 层已经剥掉了。透明渲染可以做得一样：**每一遍绘制，只取"当前所有透明层里最前面的那一层"**——这一层就是深度测试的天然胜利者。第一遍拿走最前层，第二遍拿走"剩下的里面最前面的"（即第二层），第三遍第三层……直到某个像素上再没有层了。这个"逐层剥取"的操作，有个很形象的名字：**深度剥离（Depth Peeling，PEEL 就是剥皮的意思）。**

关键的技术点在第一遍之后：第二遍怎么保证"只拿第二层，不碰第一层"？办法是把**第一遍剥出的深度当成门槛**——凡是深度比这个门槛还近（或相等）的片段全部弃掉，剩下的片段里再做普通深度测试，取最前面那个。剥几层，就设几次门槛；每次都把"已经剥过的深度"记在上一遍的结果里。

```
第 1 遍：普通绘制，深度测试拿最前层 → 记下深度 d₁ 和颜色
第 2 遍：弃掉所有深度 ≤ d₁ 的片段，剩下的取最前 → 第二层，记下 d₂
第 3 遍：弃掉所有深度 ≤ d₂ 的片段，剩下的取最前 → 第三层，记下 d₃
……
第 k 遍：弃掉所有深度 ≤ d₍ₖ₋₁₎ 的片段，取最前 → 第 k 层
当某一遍没有任何片段通过 → 所有层剥完，结束

每剥出一层，先把这层（颜色+深度）存下来
全部剥完后，把各层从远到近依次混合进最终颜色
（剥取顺序是前→后，倒过来用就是远→近）
```

这套方案诚实地说一说代价：

| 收获 | 付出的代价 |
|---|---|
| **逐像素精确**：每个像素的层序由其真实深度决定，混合结果 100% 正确——这是"排序"永远给不了的 | **Pass 数量 = 最深的层数**：场景有 10 层透明叠加就要画 10 遍，每遍都重跑一遍全部几何处理 |
| 无"贪心猜测"，结果可复现 | 每一层都要存下一张"剥离结果"（深度+颜色），显存随层数线性增长 |
| 硬性上限可预测（层数固定时开销固定） | 层数不定（粒子成千上万层时）开销爆炸，只能靠硬性截断，截断处出现穿帮 |

两个实用的工程改进（了解即可）：一是**先画一遍查一查**——某遍结束时统计通过片段数，为零就提前结束循环，避免为不存在的高层数白跑；二是**双深度剥离（Dual Depth Peeling）**——同一遍里从前面剥一层、从后面剥一层（前后各设一个门槛），层数减半；更激进的还有一次剥多层的变种。但这些都改变不了一个事实：**深度剥离的正确性按层数线性收费，层一多，账单就付不起。**

## 问题 3：能不能不逐层，一遍算出个"差不多对"？——加权平均（Weighted Blended OIT）

烟雾粒子这种场景，层数可能上百，深度剥离直接破产。能不能牺牲一点精确性，把代价压成常量？

回到混合方程本身，看它为什么"吃顺序"。精确混合是递归的：每一层的可见度 = 自己的不透明度 × 前面所有层透射下来的光。顺序在"前面所有层"这个词里——换了顺序，"谁在前面"就变了。

数学家会立刻想到：**如果放弃"递归削弱"，改用"独立加权求和"，顺序就被抹掉了。** 就像求平均值：不管先加哪个数，平均结果一样。OIT 家族的第二条路就是这么干的——**加权平均（Weighted Blended OIT，WBOIT）**：

```
第 1 遍（累积）：把不透明背景画好，然后对每个透明片段：
    按深度给一个权重 w（离相机近的层权重大——符合直觉：近的看得清）
    颜色累积   += w × 不透明度 × 颜色
    权重累积   += w × 不透明度
    透射累积   += 透射率的近似量（多层叠加的后台淡化程度）
    → 得到两三张屏幕大小的"累积图"，与层数无关

第 2 遍（合成）：全屏画一次：
    用累积量还原出最终透明颜色，与背景混合
    → 完成，总共 2 个 Pass，层数多少都一样
```

对比一下两条路的信息结构：

```
深度剥离（精确）      加权平均（近似）

每个像素记 N 层         每个像素记 3 个数
（深度+颜色）×N 张图   （颜色累积、权重累积、透射近似）×1 张图
N 个 Pass               2 个 Pass
层越多越贵              恒定为 2 个 Pass
结果完全正确            结果是"视觉上的近似"
```

WBOIT 的聪明之处在于妥协的可控：它把"顺序"换成"权重"，而权重是**启发式**——深度近的权重大，远的权重小。这正好模仿了真实视觉的主次关系：近处烟雾挡住远处烟雾，近处那层在平均里占大头。代价必须说清楚：

- **颜色会被"平均"**：两团一红一蓝的浓烟叠在一起，如果权重压不住，会混出一团"紫雾"——真实世界里近的那团应该完胜，但平均近似做不到"完胜"。
- **不透明度越高，误差越大**：α 接近 1 时，混合本质是"覆盖"，平均天然打不过覆盖。
- **带太强的画面要求（比如近处高光）会明显失真**。
- 好消息是：**粒子、烟雾、尘埃、光晕这类"模糊材质"恰恰是最不敏感的**——它们本身就千层万层、颜色过渡柔和，WBOIT 的误差几乎不可见，而它们的层数恰恰是深度剥离付不起的。这正是工业界把 WBOIT 和粒子系统绑定的原因。

> 中间地带：如果既想要"固定 Pass"，又想要精确一些，还有**分层加权（Hybrid Transparency）**：把视锥按深度切成几段，段内在层数少的地方做精确排序、层多的地方回落加权。概念了解即可——它再次印证：**这一家族全是"精确度 ÷ 成本"的滑块，没有免费的午餐。**

## 问题 4：所以到底用哪种？——一张决策表

阶段五的透明工具现在齐了，把三条路线放一起对账（表格只做总结，每条都已在前文展开）：

| 方案 | 正确性 | 性能 | 显存 | 适用 |
|---|---|---|---|---|
| **排序**（5.1） | 物体不交错时正确 | 1 个 Pass + CPU 排序 | 无 | 玻璃窗、少量不交错透明体——仍然是**默认首选** |
| **深度剥离** | **逐像素 100% 正确** | Pass 数 = 最大层数 | 每层一张图 | 层数可控又要求绝对正确（多层玻璃、透明 UI 前景） |
| **加权平均 WBOIT** | 视觉近似（近处权重） | **恒定 2 个 Pass** | 两三张累积图 | 粒子、烟雾、尘埃、光晕——大量低敏感材质 |

**决策规则就一句**：层数少、不交错 → 排序白拿；层数多、材质糊 → 加权平均白拿；层数可控又较真 → 深度剥离按需付费。没有一条是银弹，但也不再需要"排序玄学"。

## 问题 5：无论哪种，都越过了一条线——单 Pass 世界的边界

把视线从算法拉高一层。深度剥离要存"每一层的剥离结果"，加权平均要存"累积图"——**两种方案，无一例外，都需要先算出一个中间结果、存下来，再在后面的绘制中把它读回来用。**

这在阶段五之前从未发生过。前面所有笔记里，像素的信息只来自两个地方：**顶点带上来的**（位置、法线、UV）和**常量参数**（光照、光源、相机矩阵）。像素们彼此独立——这个像素算完颜色写进画面，跟旁边像素、跟之前画的任何东西都没有关系。那是幕一——**单 Pass 世界**——的定义。

而 OIT 的一小步——"把中间结果存下来再读"——打破了这个定义。像素开始消费"别的像素算出来的东西"了。这不是 OIT 独有的需求，它是整个幕二的共同主题：后处理要读"已经画好的画面"，阴影要读"从光源视角画的深度"，延迟渲染要读"别的 Pass 存下的几何"。**OIT 是这条路的第一次试探，而它在幕一的压轴出场，正好宣布了幕一的尽头。**

> 一句话：**"把中间结果存成可读数据"这个能力，是幕一和幕二的分水岭。** OIT 是第一个被这个分水岭逼出来的技术，而它的正式舞台，在下一幕的总开关里。

## 落地表达：这套思路在渲染器里怎么组织

推导到这里，方案已经清晰：**要么逐层剥（正确性按层数收费），要么加权累积（正确性按近似打折）——共同前提是把中间结果存下来再读。** 看各后端怎么表达这个前提。

**"把中间结果存下来再读"这个能力，各后端都有专门抽象**：

- **OpenGL** 用一个"离屏渲染目标"对象表达"画到一块不上屏的画布"——画完这张画布本身就可以当纹理读回来。一个对象包办"画到哪"和"怎么读"。
- **Vulkan / D3D12 / Metal** 把同一件事拆得更显式：Vulkan 拆成"渲染过程描述"（这一遍读什么、写什么、读写先后）和"具体图像绑定"（画到哪张图）两件事——因为它要在录制命令前就把读写关系固定下来，驱动才能做完整验证。
- 这些抽象的机制细节、坑和最佳实践，是**阶段六（画到画布上）** 的主题——本笔记只需记住结论：**OIT 已经亲手用到了"可读画布"，下一幕的每项技术都会再用它。**

**排序与 OIT 的组织位置**：深度剥离与加权平均都发生在引擎的渲染队列里——前者是"对透明队列循环执行多次剥离子队列"，后者是"透明队列只执行两次（累积 + 合成）"。自研引擎的[[Notes/SelfGameEngine/渲染管线与画面/基础粒子系统|基础粒子系统]]在选择烟雾/粒子的混合策略时，正是用这张决策表：粒子默认加权平均，特殊镜头（要求精确遮挡的爆炸核心）回退深度剥离。

## 明确推荐：一张决策清单

1. **默认还是排序**（5.1）——零额外开销，能处理日常玻璃与单层粒子；只有它明显出错时才升级。
2. **粒子、烟雾、尘埃、光晕 → 加权平均（WBOIT）**：恒定 2 个 Pass，与层数无关，对"模糊材质"的近似误差肉眼不可见。
3. **层数可控且要求逐像素正确（多层玻璃、透明前景 UI）→ 深度剥离**：提前设定最大层数，落地为显存和 Pass 预算，超过的部分用截断接受穿帮。
4. **实现顺序建议**：先做排序（验证管线正确），再加加权平均（覆盖粒子主战场），深度剥离作为按需增强——每层抽象都不要破坏前一层，因为它们在真实引擎里共存。
5. **记住分水岭**：无论选哪条，都依赖"中间结果可读"这个能力——它就是下一幕的总开关，也是阶段六的主角。

> **下一步**：进入幕二。[[Notes/计算机图形学/离屏渲染/离屏渲染与FBO|离屏渲染与 FBO]] — 像素需要的信息不再只来自顶点和常量，而是来自"别的像素、别的视角、上一帧"。这一切的总开关，是先把画面画到一张能读的"画布"上——OIT 已经替你摸过门把手了。
