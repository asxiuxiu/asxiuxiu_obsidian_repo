# 透明与混合索引

> [[Notes/计算机图形学/Roadmap|← 返回 Graphics Journey 路线图]]

本模块回答的核心问题：**不透明世界靠深度缓冲"谁在前挡住谁"；像素一旦半透明，这个简单假设就崩了。单 Pass 世界里，透明靠什么救？救到哪一步是极限？**

阶段五结束前，先记住一个觉悟：**有些透明问题，单 Pass 世界解决不了——"先画到别处，再组合"（多 Pass）是唯一的出路。** 那是幕二的入场券。

---

## 学习顺序

1. [[Notes/计算机图形学/透明与混合/混合方程与透明排序|混合方程与透明排序]] ✅
   - 像素怎么从"被替换"变成"被混合"（混合方程与 src/dst 因子）、为什么混合依赖顺序、深度测试为什么救不了透明、从远到近排序的代价与天花板
   - **问题驱动**：两块半透明玻璃叠在一起，先画谁结果完全不同。不透明物体靠深度测试乱序画都对，透明为什么不行？

2. [[Notes/计算机图形学/透明与混合/深度预Pass与Early-Z|深度预 Pass 与 Early-Z]] ✅
   - Early-Z 硬件机制、先画一遍"只写深度"的快速 Pass、overdraw 的量化、深度预 Pass 顺带简化透明排序
   - **问题驱动**：复杂场景里 overdraw 可能是 3~5 倍——每个像素被反复着色再被覆盖。能不能先廉价地铺好深度，让正式绘制时被挡像素直接丢弃？

3. [[Notes/计算机图形学/透明与混合/顺序无关透明OIT|顺序无关透明 OIT]] ✅
   - 为什么排序在三角形交错时无解、Depth Peeling 的多 Pass 剥离、Weighted Blended OIT 的单 Pass 近似、各自的显存与精度代价
   - **问题驱动**：两团烟互相穿插，任何全局排序都是错的。能不能不排序也得到"看起来正确"的透明？
   - **本阶段收尾**：Depth Peeling 已经需要"把中间结果存下来再读"——单 Pass 世界的边界到了，这是幕二（多 Pass 世界）的入场券。
