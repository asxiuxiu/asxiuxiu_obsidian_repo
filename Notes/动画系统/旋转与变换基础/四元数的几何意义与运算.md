# 四元数的几何意义与运算

> [!todo] 本篇核心问题
> 四元数到底是什么？调角色动画时，真正需要会用的是哪几招？

> [!tip] 先回答一个更实际的问题：需要懂多深？
> **不需要懂推导。** 调动画时你对四元数的全部需求是：
> 1. **知道它是什么**——"绕某根轴转某个角度"的一张处方单。调试时打印出来的四个数看不懂很正常：它存的不是角度本身。
> 2. **会用三招**——复合（两个旋转先后做）、撤销（反向转回去）、插值前的符号检查。
> 3. **记住几条避坑规矩**——乘法顺序、轴要归一化、定期"消毒"。
>
> 至于内部乘法怎么展开、旋转向量为什么是 `qvq*` 这种形式，引擎的 `FQuat` 已经封装好了。本篇把这些推导收进折叠区块——不看也完全不影响读懂后面所有笔记。

## 为什么需要解决这个问题

调动画时要处理旋转的地方多得数不清：这一帧的姿势该转多少度、两段动画之间怎么过渡、手里的武器怎么跟着手腕走。而计算机里能拿来存旋转的东西，打印出来是一串**四个看不出含义的浮点数**——`(0.866, 0.289, 0.289, 0.289)` 到底是什么意思？不知道它怎么来的，你就没法判断"这个值对不对"。

所以本篇要先把四元数这个概念本身立起来——它到底在表达什么、调动画时真正用得上的操作是哪几个。

> [!note] 先钉一个词：这里的"骨骼"是什么
> 后面几招都要用到这个词，所以先花两句话说清：游戏里的**骨骼**不是解剖学上那根有长度有粗细的骨头，而是一个**没有长度的坐标架**（原点 + 朝向）——它是"这一节肢体此刻在哪儿、朝哪边"的标定物。真实的骨头长度在游戏数据里表现为"子关节相对父关节的偏移量"。
> 说到这里够用了；骨骼为什么必须组成一棵树、参考姿势是什么，是后面 [[Notes/动画系统/角色资产与骨骼基础/骨骼的本质：从骨架到 Skeleton 资产|骨骼的本质：从骨架到 Skeleton 资产]] 篇的整篇内容——**你现在只需要知道"骨骼 = 一个能转的坐标架"，本篇讲的旋转，作用的就是它。**

## 直观理解：旋转 = 一张处方单

想象你开一张处方单，上面只写两行字：

> 【绕哪个轴转】axis = (0.577, 0.577, 0.577)
> 【转多少度】angle = 60°

**这就是三维旋转的全部信息。** 不管多复杂的姿态变化，拆到最底层，每次旋转就是"绕某根轴转某个角度"。四元数的本质，就是把这张处方单**打包成 4 个数字**的数学结构，让计算机能高效地做三件事：复合、撤销、旋转向量——这也就是下面三招要讲的全部内容。

关于这张处方单，有一条规矩必须现在就钉住，因为后面的坑都从它来：

- **轴是方向，不是位置**：`(0.577, 0.577, 0.577)` 回答的是"往哪转"，不回答"轴在哪"。正因为它只表达方向，**三个数只有相对比例有意义**——所以规矩是**模长必须为 1（归一化）**，方向里不许混进"长度"。

那"轴在哪条线上"这个问题谁管？**Transform 的 `position` 分量单独管。** 角色在世界里站在哪、骨骼的原点在哪，是平移分量的事，和旋转**分家管理**——所以处方单不需要回答它。记住这个分家，后面 [[#边界与坑]] 里那条"角色越算越胖"的坑，就是它的直接后果。

## 核心机制

### 调试时打印出来的数看不懂：半角

你 print 一个四元数，看到 `(0.866, 0.289, 0.289, 0.289)`——这跟"转 60°"有什么关系？

关系是：四元数**不直接存角度，存的是半角的 sin/cos**：

$$
q = (\cos\frac{\theta}{2},\ \sin\frac{\theta}{2} \cdot axis)
$$

验算一下：60° 的半角是 30°，cos30° ≈ 0.866，sin30° ≈ 0.5，0.5 × 0.577 ≈ 0.289——正好对上。

**为什么故意折半？** 属于内部机制需要（旋转向量时从两侧各出半程，合起来正好 θ），不知道完全不影响使用。你只要记住结论：**四个数 = 半角余弦 + 半角正弦×轴**，所以肉眼读不出角度；想知道是几度，用引擎现成的换算接口转回去看就行。

### 第一招：复合 —— 两个旋转先后做

**复合的意思是"把先后两次旋转叠成一次"。** 你不是每次只想转一下——角色这一帧的姿势，往往是好几股旋转堆出来的。与其每次执行一张处方单，不如先把它们乘成一张，再一次执行完。

> 场景：角色头部（同一根骨骼）要先后做两个局部旋转——先绕 Y 轴**向右转 90°**（q₁），再绕 X 轴**低头 90°**（q₂）。既然都是"这张处方单做完、接着做那张"，能不能合成一张处方单，一次执行完？

能，而且合成的办法就是四元数乘法：

```
q_total = q₂ × q₁
```

这张新处方单的效果，和"先做 q₁，再做 q₂"完全一样——**两张处方单变成一个数**。

**读法：先做的写在乘号右边**。这跟函数复合 `f(g(x))` 的规则一致：f 在左、g 在右，先执行 g。所以看到 `q₂ × q₁`，不要从左边开始读，要从右边开始读。

**顺序敏感，交换不成立**：

```
q₂ × q₁  ≠  q₁ × q₂
```

几何上可以直观感受：先向右转再低头，和先低头再向右转，最终头部朝向不一样。**如果你的角色在某个角度下"姿势错位"，最可能的嫌疑就是乘法顺序写反了。**

> [!note] 为什么"转体 + 举臂"不在这套话里？
> 如果你想到的是"转体之后举手，和举手之后转体，明明最后一样"——那不算矛盾：**转体**作用在根骨（脊柱），**举臂**作用在手臂，两股旋转落在**不同的骨骼**上，各走各的层级，顺序被骨架解耦了，确实怎么排都一样。这里讲的顺序敏感，前提是两股旋转落在**同一根骨头**（如这里的头、或某个肩关节）上、在同一局部空间里先后叠加，这时才存在"先做谁"的问题。

动画里最常遇到这套乘法的地方是骨骼层级：子骨骼的世界旋转 = 父骨骼的世界旋转 × 子骨骼的局部旋转——这正是 [[Notes/动画系统/旋转与变换基础/变换层级与复合变换|变换层级与复合变换]] 篇的核心操作。

### 第二招：撤销 —— 共轭与逆

> 场景：角色做完一套动作要回到初始姿势；或者要算"从当前姿势到目标姿势还差多少"。

**共轭**：虚部取反，`q = (w, x, y, z) → q* = (w, -x, -y, -z)`。几何含义：**绕同一根轴、反向转 θ**。

**求逆**：`q⁻¹ = q* / |q|²`。但对**单位四元数**（纯旋转全是单位四元数），`|q|² = 1`，所以 **逆 = 共轭**——动画引擎里 99% 的"撤销"就是虚部取反，一行的事。

"撤销"在动画里的高频用途：

- 算两个姿势的**差异**：`q_diff = q_target × q_current⁻¹`——想要"在基准姿势上再叠一点动作"的 [[Notes/动画系统/混合空间与Additive/Additive动画：叠加与增量姿势|Additive 动画]]，就是靠它算出那个偏差量（增量）；
- 把世界空间的骨骼方向**反解回局部空间**——回看上面那条"分家管理"的规矩：用来看的姿势在世界空间，用来存的却在局部空间，想拿世界里的目标去驱动一根骨骼，就得先把它反解回去。**重定向**（把一套动画搬到另一副骨架上）和 **IK**（逆向运动学：给定手/脚要到的位置，反推各关节转多少，详见 [[Notes/动画系统/逆向运动学/逆向运动学：从末端反推骨骼姿势|逆向运动学]] 篇）里大量使用这一招。

### 第三招：旋转向量 —— 知道有这回事就行

前面两招折腾的对象都是旋转本身。这一招不一样：被处理的是**向量**——比如一根骨骼的朝向、摄像机的前方方向。需求很朴素："按这张处方单，把它掰到新方向去。"

先把第一个容易混的地方摆平：**向量和处方单里的轴，是两码事**。处方单里的轴是"转盘的中心轴"，向量是"被转的那个箭头"，两者方向通常不一样——就像地球仪绕地轴转，地轴是转轴，而你要转的是地球仪上某根指向某个城市的箭头，箭头当然不跟地轴平行。唯一会重合的情况：箭头恰好躺在转轴上，那它怎么转都是自己（下面折叠区里就用到了这一点）。

公式长这样：

```
v' = q × v × q*
```

读法：**拿 q 从左边乘一下 v，再拿 q* 从右边乘一下**，出来就是转好的向量 `v'`。`q*` 就是上一招学过的共轭（虚部取反）。同一样东西从两边各夹一下，所以叫"两面夹击"。

**为什么两边要夹的不一样？** 差别只在虚部的符号：左边是 q，右边是 q*（带星号的共轭）。原因是两边各负责半程——`q` 从一侧转半个角度，`q*` 从另一侧再补半个角度，合起来正好转够整个 θ。而且右边必须用共轭，不然转出来的东西不再是纯向量，而是一个带着实部"尾巴"的四不像；要求结果仍是向量，就只能这么配。这两句解释背后的推导收在下面的折叠区，不展开也不影响使用。

**你几乎不需要手写它**——引擎里就是一行 `RotateVector` 调用，知道"四元数能直接把向量转过去"这个事实就够了。

> [!note]- 想深究：两面夹击为什么成立
> 把向量拆成两段：沿轴分量（绕自己的轴怎么转都是自己，夹击对它毫无影响）和垂直分量（左乘 q 转半程 θ/2，右乘 q* 在同一平面再补半程 θ/2，合起来正好 θ）。只乘一次不行，因为结果会带一个非零实部的"尾巴"，不再是纯向量——两面夹击同时保证了"转够 θ"和"结果仍是向量"。

> [!note]- 想深究：四元数乘法怎么展开
> 乘法按 **Hamilton 规则**展开（以发明四元数的数学家命名）：实部是 `w·w' − v·v'` 式的点积差，虚部是交叉项组合。引擎的 `FQuat::operator*` 就是这个展开式。日常使用中把它当黑盒即可。

### 彩蛋：q 和 -q 是同一张处方单

把处方单 `q` 的四个数整体取负得到 `-q`，代入旋转公式会发现负号乘了两次、恰好抵消——**q 和 -q 描述的是完全相同的旋转**（这叫"双重覆盖"）。

这不是数学冷知识，而是混合动画时的实操规矩：两个来源不同的采样结果，可能一个是 q、一个是 -q。**直接对它们插值会绕一整圈远路**——该转 30° 的过渡，角色转了 330°。所以引擎在插值前会先算两个四元数的点积，**点积 < 0 就把其中一个取负**，让两张处方单"靠到同一半球"。这是 [[Notes/动画系统/旋转与变换基础/四元数插值：Slerp与归一化|Slerp 与归一化]] 篇的先决条件。

## 边界与坑

- **乘法顺序写反**：先做 A 再做 B 要写成 `qB * qA`（见上文第一招）。
- **q 和 -q 是同一姿态**：混合/平均前先检查点积，异号就翻其中一个（见上文彩蛋）。
- ~={red}**轴必须归一化**：构造处方单前 `n /= length(n)`。模长 ≠ 1 的四元数是"旋转 + 缩放"的混合体，动画里表现为角色越算越"发胖"。=~
- **数值漂移要归一化**：连续几十次复合会把模长慢慢拉离 1，用久了 `q /= |q|` 纠偏（UE 的 `FQuat::GetNormalized` 就是干这个的）。
- **零角度**：θ = 0 时 `q = (1, 0, 0, 0)` 即恒等。此时轴的取值无意义，拿它做归一化要当心除以零。

## 一句话总结

四元数 = "轴 + 角度"处方单的半角打包（所以打印出来看不懂很正常）；调动画真正要会的是三招——复合（顺序敏感，先做的写右边）、撤销（单位四元数下逆 = 共轭）、插值前查点积翻符号——外加"轴归一化、定期消毒"的卫生习惯；其余推导细节，交给引擎。
