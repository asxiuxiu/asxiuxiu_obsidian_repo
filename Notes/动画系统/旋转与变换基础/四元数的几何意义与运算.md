# 四元数的几何意义与运算

> [!todo] 这篇笔记解决什么问题
> 四元数怎么用四个数字表示旋转？它到底在说什么？我该怎么用？

## 为什么需要先绕几个弯

上一篇《旋转的三种表示》定下一个分工：角色真正动起来之前，内部的旋转**统一用四元数存、用四元数算**。但如果你直接跳到四元数公式，很容易被三个问题砸晕：

1. **这几个数字是什么？** `(0.866, 0.289, 0.289, 0.289)`——看着像坐标但又不像，到底代表什么？
2. **为什么旋转要四个数？** 三维空间的东西，三个数不是已经能表示位置了吗？
3. **"绕斜轴转"里的斜轴到底在哪？** 三个数只给了方向，但同方向有无数条直线，怎么确定绕哪条？

如果你也卡在这三个问题上——**很正常，不是你的问题，是大多数教程跳过了太多"默认你懂"的预备知识。** 这篇笔记会从最基础的"三个数字在坐标里能装什么"开始，一路铺到四元数的三招操作，每一层都让你能"看见"它在说什么。

---

## 预备知识一：同一组 (x,y,z)，装的是不同东西

同样三个数字，在图形学里可以表示两种完全不同的信息。

**位置——回答"你在哪"**

> `(1, 1, 1)`：从原点出发，沿 x 走 1 米、沿 y 走 1 米、沿 z 走 1 米，**到达一个确定的点**。

这里的 `(1, 1, 1)` 像一个 GPS 坐标——它告诉你一个点在空间里的**具体位置**。三个数字的绝对大小（离原点多远）是有意义的，1 就是 1 米，不是 0.5 米。

**方向——回答"你往哪看"**

> `(0.577, 0.577, 0.577)`：往 x 偏 0.577 份、往 y 偏 0.577 份、往 z 偏 0.577 份。

这里的三个数字只有**相对比例**有意义——"同等分量往 x/y/z 三个方向偏"，至于"总的走了多远"不重要，因为方向不关心距离。所以方向向量进出规矩：**必须归一化（模长 = 1）**，确保它只携带"方向"信息，不往里混进"长度"。

> 0.577 这个数字从哪里来？这条轴的本体是体对角线 `(1, 1, 1)`，但它的长度是 √3 ≈ 1.732，里面混进了长度。把每个分量除以 1.732，缩成模长 = 1 的纯方向，就得到 `(1/√3, 1/√3, 1/√3) ≈ (0.577, 0.577, 0.577)`。计算机在构造旋转时，第一步就是检查轴向量是否归一化——因为旋转不认"带长度的轴"。

| 概念 | 三个数字 | 模长 | 你理解成 |
|------|----------|------|----------|
| **位置** | `(1, 1, 1)` | √3 ≈ 1.732 | "那个点就在那" |
| **方向** | `(0.577, 0.577, 0.577)` | 1 | "往那个方向看" |

回到四元数的处方单，第一行 `axis = (0.577, 0.577, 0.577)` ——它是一个**方向向量**，回答的是"轴朝哪指"，不回答"轴在哪个位置"。

## 预备知识二：旋转需要几个信息？

**二维空间里，旋转只需要一个数：角度。**

因为二维平面只有一个自由度——你只能绕"垂直于平面的那根轴"转，没有别的选择。所以 `θ = 45°` 就说清楚了。

**三维空间里，你多了一个选择：先选"绕哪根方向"，再选"转多少度"。**

- 轴：一个方向向量（3 个数），比如 `(0.577, 0.577, 0.577)`
- 角度：一个数（1 个数），比如 `60°`

所以三维旋转的"总信息量"是 **4 个数**。后面的四元数正好塞进 4 个数 `(w, x, y, z)`——你看，它本来就不是 3 个数的东西。

> 你现在可能松一口气：原来"三数字表示斜轴"不是把旋转压缩到 3 个数字里，而是旋转的 4 个信息中，**轴占了 3 个，角度占了 1 个**，加在一起刚好 4 个。所以四元数叫"四元数"——它需要四个数。

---

## 预备知识三：轴到底在哪条线上？

现在你可能还有一个更深的疑问：

> "轴是一个方向向量，它只说了'往哪指'，但世界空间里朝这个方向的直线有无数条——过原点的、过 (100,0,0) 的、过 (-5,3,2) 的……你的三个数只说了方向，**没说是哪条线**！"

**你说得完全对。** 方向向量确实只确定了"平行线族"，不等同于一条具体的直线。要唯一定义一条直线，你需要 **方向 + 一个经过的点**。

### 那旋转用的是哪条线？

**数学上，"绕轴旋转"这个操作被严格定义成：绕穿过原点的那条直线旋转。**

所以：

> 方向向量 `(0.577, 0.577, 0.577)` + 一个隐含的约定"轴过原点" = 唯一一条直线。

方向向量本来就唯一确定了从原点出发的那条射线，而"过原点"就是这个约定，让方向向量从"平行线族"变成了"唯一一条直线"。

### 但物体在世界空间有位置啊——它轴不在原点怎么办？

这是最精彩的地方。**引擎把"位置"和"旋转"分家存了。**

每个对象/骨骼的变换（Transform）是这么存的：

| 分量 | 作用 | 数据结构 |
|------|------|----------|
| **位置 (translation)** | "物体在世界空间哪个点" | 一个 `vec3`（3 个数） |
| **旋转 (rotation)** | "物体自身的坐标轴往哪边倾" | 一个四元数（4 个数） |
| **缩放 (scale)** | 可选 | 一个 `vec3` 或一个数 |

**旋转永远只回答"物体自身在原点时该如果转"这个问题。** 位置由 `position` 单独回答。两者合在一起（通过 `T × R` 矩阵乘法），才得到"物体在世界里某个位置以某个姿态出现"。

> 你之前担心的"方向相同但位置不同的直线有无穷多条"——**没错，但旋转操作根本不关心"位置"那部分信息，它只关心"方向"那部分。** 位置被 `position` 独立管了。正是这个"分家"的设计，让旋转只用方向向量就能精确定义，不再需要额外说"轴在哪条线上"。

---

经过三层预备知识，你现在应该能相信：

- `(0.577, 0.577, 0.577)` 是**方向向量**，不是位置坐标
- 3D 旋转需要 **4 个数**（方向 3 个 + 角度 1 个）
- 轴固定过原点，所以方向向量唯一确定一条线
- 物体的位置和旋转是分开存的，互不干扰

**现在可以正式介绍四元数了。**

## 直观理解：一张「旋转处方单」

想象你不想亲自调角度，于是开了一张**处方单**，上面写着两行字：

> 【绕哪个轴转】axis = (0.577, 0.577, 0.577) —— 一条斜轴
> 【转多少度】angle = 60°

四元数就是把这张处方单**打包成一个 4 元组**的数学结构。但打包的方式有点反直觉：

- 它不直接存 60°，而是存 **cos(30°)** 和 **sin(30°) × 轴**，即 **半角**。
- 于是 `q = (cos30°, sin30°×0.577, sin30°×0.577, sin30°×0.577) = (0.866, 0.289, 0.289, 0.289)`

**为什么故意折半？** 因为四元数旋转向量时要**从两面夹击**——左乘一次 q、右乘一次 q 的共轭——每一面贡献"半程旋转"，合起来正好是一整份 θ。后面会展开讲。

**三个运算就是把这张处方单用在不同场景：**

- **旋转**：把处方单"作用"到向量上，让向量转起来
- **复合**：把两张处方单"合成"一张，一步到位
- **撤销**：把处方单"反转"，退回起点

这三招在动画数据流中的位置是：**在「采样→混合→蒙皮」的每一站，只要涉及旋转，底层都在跑这三招之一**。位置和缩放是线性量，直接加加减减就行；旋转是唯一必须用"专用语言"处理的分量。

## 核心机制：三个几何操作

### 第一招：旋转一个向量 → 两面夹击 `v' = q v q*`

> 场景：角色投篮时，小臂从下垂位置转到指向篮筐的方向。小臂方向是一个向量 `v`，绕肩关节轴 `n` 旋转 θ 度。这个操作在动画每帧每个骨骼上都会发生。

**Step 1：把向量包装成四元数**

三维向量 `v = (x, y, z)` 不能直接跟四元数乘。标准做法：把它当成一个"实部为 0 的四元数"：`ṽ = (0, x, y, z)`。

**Step 2：两面夹击公式**

```
ṽ' = q × ṽ × q*
```

- `q` 是那个半角处方单
- `q*` 是 q 的**共轭**（虚部取反），即"反向半程处方单"
- 先左乘 q，再右乘 q*，等于把这套旋转"夹"在中间

**Step 3：为什么需要两面夹击？**

想象一下：你站在一根绳子中间，左手把绳子往左拧半圈、右手把绳子往右拧半圈。绳子中间被拧了多少？一整圈。

同理：
- 左乘 `q`：把向量向前推了半程 θ/2
- 右乘 `q*`：把向量向后回拉了半程 -θ/2（因为共轭是反向的）
- 合起来，向量恰好转了整整 θ

**为什么不能只乘一次？** 因为四元数乘法是四维的，而向量是三维的。如果只乘一次（`q × ṽ`），结果会有一个实部不为 0 的"尾巴"——它不再是纯向量，不能用来表示位置或方向。**两面夹击的作用之一就是保证实部永远为 0，结果永远是纯向量。**

> 一句话记住第一招：**用 q 左夹、用 q* 右夹，向量转 θ，结果还是向量。** 这正是引擎里 `FQuat::RotateVector` 做的事（见文末引擎落地）。

### 第二招：合成两步旋转 → 乘法复合 `q_total = q₂ × q₁`

> 场景：角色既要做"向右转体 30°"（q₁），又要做"举臂 45°"（q₂）。能不能把这两步合成一张处方单，之后只执行一次？

可以，用四元数乘法。

**写法：**
```
q_total = q₂ × q₁
```

**读法：**"先做 q₁ 的旋转，再做 q₂ 的旋转"。**注意顺序**——左边的 q₂ 是后做的，右边的 q₁ 是先做的。这跟矩阵乘法、函数复合的规则完全一致：`f(g(x))` 表示先做 g 再做 f，写在纸上是 f 在左、g 在右。

**顺序敏感——交换不成立：**

```
q₂ × q₁  ≠  q₁ × q₂
```

几何上合理至极：先向右转体再举臂，和先举臂再向右转体，最终姿态不一样。就好比"先开罐头再喝水"和"先喝水再开罐头"——两个动作的先后顺序确实改变了结果。

> 一个数值验证：绕 X 轴转 90° 的 q 和绕 Y 轴转 90° 的 q，交换顺序后得到完全不同的结果。如果你的动画角色在某个角度下"姿势错位"，最可能的原因之一就是乘法顺序搞反了。

**在动画数据流中的位置：** 骨骼层级复合就是这套乘法的典型应用。父骨骼的旋转（q_parent）和子骨骼的局部旋转（q_child）合成子骨骼的世界旋转：
```
q_child_world = q_parent × q_child
```
这正是 [[Notes/动画系统/旋转与变换基础/变换层级与复合变换|变换层级与复合变换]] 篇的核心操作。

> 一句话记住第二招：**顺序敏感。左起读是"先做右侧那个、后做左侧那个"；想合成，把先做的放在乘号右边。**

### 第三招：撤销旋转 → 共轭与逆

> 场景：角色做了整套投篮动作，现在要回到初始姿势。或者，你需要计算"从当前姿势到目标姿势的旋转差异"——这就用到了"反向"操作。

**共轭（Conjugate）——把虚部取反**

```
q = (w, x, y, z)  →  q* = (w, -x, -y, -z)
```

几何含义：**绕同一根轴、反向转 θ**。因为 `q = (cos(θ/2), sin(θ/2)·n)`，取反虚部得到 `(cos(θ/2), -sin(θ/2)·n) = (cos(-θ/2), sin(-θ/2)·n)`，正是绕同一轴转 -θ。

**求逆（Inverse）——共轭 ÷ 模长平方**

```
q⁻¹ = q* / |q|²
```

对于**单位四元数**（所有纯旋转都用单位四元数），`|q|² = 1`，所以 `q⁻¹ = q*`。动画引擎里 99% 的场景下"求逆"就是"取共轭"。

**"撤销"的几何意义：**

```
q × q⁻¹ = 恒等（不做任何旋转）
```

先转再撤回来 = 没转。这个操作在动画里频繁出现，例如：
- 把世界空间的骨骼方向反解到局部空间（重定向、IK 中大量使用）
- 计算两个旋转之间的"增量"：`q_diff = q_target × q_current⁻¹`
- 把某个方向的旋转消除掉，只保留另一方向的旋转

> 一句话记住第三招：**单位旋转四元数的逆 = 共轭 = 绕同一根轴反着转。** 如果你构建处方单时轴没归一化、模长不是 1，用逆时务必用完整公式 `q⁻¹ = q* / |q|²`，不要只取共轭。

### 贯穿三招的彩蛋：q 和 -q 是同一个旋转

把 `q = (cos(θ/2), sin(θ/2)·n)` 整体取负，得到 `-q = (-cos(θ/2), -sin(θ/2)·n)`。代入 `v' = q v q*`：

```
(-q) × v × (-q)* = (-q) × v × (-q*) = q × v × q*
```

因为负号乘了两次，抵消了。所以 **q 和 -q 描述的是完全相同的旋转**。这叫"双重覆盖"（double cover）。

**这个彩蛋在动画里极其重要：** 当你要对两个几乎一样的姿势做平均（比如两个动画采样结果非常接近，但一个来自 q、一个来自 -q），直接相加平均会走出绕一整圈的远路。动画引擎在插值前会检查点积，点积 < 0 就翻转其中一个，强制同号——这是 [[Notes/动画系统/旋转与变换基础/四元数插值：Slerp与归一化|Slerp 与归一化]] 篇的先决条件。

## 代码表达：三招合一的骨架

下面这段代码不求可运行，只求把三招的结构写清楚。抓住三个关键点：
1. `makeRot` 里的 `half = deg * 0.5f` 就是半角
2. `mul(mul(q, v), conj(q))` 就是两面夹击
3. 想撤销，把 q 换成 `conj(q)`

```cpp
// flags: -O0 -g
#include <cmath>

struct Quat { float w, x, y, z; };

// [半角处方] 绕单位轴 (ax,ay,az) 旋转 deg 度
Quat makeRot(float ax, float ay, float az, float deg) {
    float half = deg * (3.14159265f / 180.f) * 0.5f;
    float s = std::sin(half);
    return { std::cos(half), ax*s, ay*s, az*s };
}

// [复合] q2 * q1 = 先做 q1 再做 q2（顺序敏感）
Quat mul(const Quat& p, const Quat& q) {
    return {
        p.w*q.w - p.x*q.x - p.y*q.y - p.z*q.z,
        p.w*q.x + p.x*q.w + p.y*q.z - p.z*q.y,
        p.w*q.y - p.x*q.z + p.y*q.w + p.z*q.x,
        p.w*q.z + p.x*q.y - p.y*q.x + p.z*q.w };
}

// [共轭] 单位旋转四元数的逆 = 共轭（虚部取反）
Quat conj(const Quat& q) { return { q.w, -q.x, -q.y, -q.z }; }

// [旋转] 两面夹击：v' = q * v * q*
void rotate(const Quat& q, float& vx, float& vy, float& vz) {
    Quat v{0, vx, vy, vz};
    Quat r = mul(mul(q, v), conj(q));
    vx = r.x; vy = r.y; vz = r.z;
}
```

读这段时抓住三点：① `makeRot` 里那个 `0.5f` 就是「半角」；② `mul(mul(q, v), conj(q))` 正是"左夹 q、右夹 q*"的结构；③ 想撤回到起点，把上面的 `q` 换成 `conj(q)`（单位四元数下等于 `q⁻¹` 反向转）。结构对了，概念就通了——数值只是上述事实的机械印证。

## 边界与坑

- **轴必须归一化**：构造处方单前务必 `n /= length(n)`。模长≠1 的四元数会同时带旋转和缩放，动画里表现为角色越算越"发胖"或长度漂移。
- **q 和 -q 是同一姿态（双重覆盖）**：混合/平均前先检查点积，异号就翻其中一个，避免插值绕远路。
- **乘法顺序即旋转顺序**：先做 A 再做 B 要写成 `qB * qA`，写成反序是另一个姿态——这是动画动作错位最常见的原因。
- **数值漂移要归一化**：连续几十次复合会把模长慢慢拉离 1，用久了要 `q /= |q|` 纠偏（UE 的 `FQuat::GetNormalized` 正是为此）。
- **零角度**：θ=0 时 `q=(1,0,0,0)` 即恒等。此时轴的取值无意义，若拿它做归一化再旋转要当心除以零。

## 一句话总结

四元数以半角存「绕单位轴转 θ」的处方；对向量用 `q v q*` 两面夹击完成旋转；乘法 `q₂×q₁` 等价于「先做 q₁、后做 q₂」（顺序敏感，不交换）；求逆在单位四元数下退化为共轭（虚部取反），几何含义是绕同一根轴反向退回起点。三招齐备，四元数才能真正成为动画系统里"在机器里跑"的旋转运算对象。
