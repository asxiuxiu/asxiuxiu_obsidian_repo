# 按骨骼混合与Mask

> [!todo] 本篇核心问题
> 如何让上半身攻击、下半身继续走路？Mask 怎么划分骨骼？

## 为什么需要解决这个问题

先看一个射击游戏里天天出现的画面：**角色一边跑一边开枪**。

这件事在资源层面是两段动画：一段全身体的**跑步循环**，一段**只有上半身有内容**的开枪循环。它们必须**同时生效**——腿在跑，胳膊在开枪。

（零假定：这里的**骨骼**指动画驱动的一根根关节，每根记着自己的位置和朝向，"腿在跑"就是大腿、小腿、脚这几根骨骼的数值在变；**姿势**则是某一瞬间所有骨骼数值的完整快照。不熟悉的话先看 [[Notes/动画系统/角色资产与骨骼基础/骨骼的本质：从骨架到 Skeleton 资产|骨骼的本质：从骨架到 Skeleton 资产]] 和 [[Notes/动画系统/动画播放与混合/姿势混合：加权与跨渐变#姿势是什么：一整份「所有骨骼的局部变换」|姿势是什么]]——本篇不重复讲，只讲"怎么让它们分区生效"。）

看上去只要把两段动画混起来就行。但上一篇 [[Notes/动画系统/动画播放与混合/姿势混合：加权与跨渐变|姿势混合：加权与跨渐变]] 教的混合，是**给整个姿势配一个权重**：`结果 = A × (1-α) + B × α`。这里 α 是"整副骨架一份"的数字，它一视同仁地作用在每一根骨骼上。

于是把跑步（A）和开枪（B）整体混起来，会发生两件都不想要的事：

**第一件，腿被稀释了。** 开枪动画里的腿是**站着不动**的姿势。α = 0.5 时，每条腿的最终姿势是"跑步腿"和"站立腿"各一半——大腿摆幅减半、小腿抬不起来。角色看起来像**在跑又没在跑**，脚在地上蹭，滑步，一条腿想抬又抬不起来的鬼姿势。

**第二件，那个权重本来就找不到一个能用的值。** 跑步是循环，开枪也是循环，两者的播放进度**对不上拍**，腿和胳膊各自走到哪一帧是随机的。α 调到接近 0，开枪动作几乎看不见；α 调到接近 1，腿被拖成半个站立。想两头都要，等于要求一个数字同时满足两组互相矛盾的百分比——无解。

问题不在权重数值上，而在**"整副骨架只有一个权重"这个前提本身**。腿该听跑步的、胳膊该听开枪的——**每根骨骼该有自己的答案**。本篇要讲的机制，就是把"一个权重的混合"升级成"**逐骨骼各自有权重的混合**"。

## 直观理解：调色师的选区

用一个贯穿全篇的比喻。

**整体混合 = 给整幅画加一层半透明滤镜。** 你把"跑步画面"和"开枪画面"叠在一起，一视同仁地各取一半。得到的是一张**糊掉的画**：两条腿也糊了，两只手也糊了——你没法说"只要手的部分糊、腿的部分保持清晰"。

**按骨骼混合 = 先画一个选区，只在选区内做叠加。** 你圈定"上半身"这块区域，让开枪画面只在圈里生效；圈外的下半身**原封不动**保持跑步。同一张画面上，腿是清清楚楚的跑步姿势（权重 100%），胳膊是清清楚楚的开枪姿势（权重 100%），而不是两块糊在一起的东西。

那个"选区"，就是 **Mask（遮罩）**。先记住它此刻的作用就够了：**一次混合里，它规定"允许作用在哪些骨骼上"**。至于它凭什么能这么规定、它的数据长什么样，正是第二节要看的。

```
数据流位置：
  跑步姿势 ─┐
            ├─ 按骨骼混合 → 最终姿势
  开枪姿势 ─┘        ↑
                  Mask（逐骨骼选区）
```

（零假定：这里的"骨骼（Bone）"指的是骨架里的一根根关节，每根都有自己的局部变换——不熟悉的话先看 [[Notes/动画系统/旋转与变换基础/变换层级与复合变换|变换层级与复合变换]]。）

本篇待在动画链路的**混合站**：输入端是两个姿势 + 一张 Mask，输出端是一个**在部分骨骼上被替换过**的姿势。它不改变混合的数学，改变的是"**哪个权重作用在哪根骨骼上**"。

## 核心机制

### Mask 是什么：一张逐骨骼的权重表

Mask 只认"第几号骨骼"这个序号，所以先把这个序号从哪来交代清楚。

（零假定：**Skeleton**——直译"骨架"，它是骨骼层级本身被单独拆出来的一份资产：一根骨骼叫什么名字、父级是谁、参考姿势长什么样。**动画数据挂在它上面，而不挂在具体的模型网格上**——所以同一个角色的五套装备、三套模型精度，可以共用一份骨架和一套动画。它为什么必须独立成资产，见 [[Notes/动画系统/角色资产与骨骼基础/骨骼的本质：从骨架到 Skeleton 资产#关键决策：为什么必须把 Skeleton 拆成独立资产|骨骼的本质：从骨架到 Skeleton 资产]]。这里只需要记住一句：**Mask 里说的"第 3 号骨骼"，指的是某一份 Skeleton 里的第 3 号。**）

Mask 的数据结构朴素到不像个概念：

```cpp
// flags: -O0 -g

// 一张 Mask：每根骨骼一个 0~1 的权重
// 索引与 Skeleton 的骨骼一一对应
struct BoneMask {
    std::vector<float> BoneWeight;   // 长度 = 骨骼数量
};
```

每根骨骼存一个 `0~1` 的值，含义只有一句：

- **1** → 这根骨骼**完全用 B 的姿势**（被替换）；
- **0** → 这根骨骼**完全用 A 的姿势**（不受 B 影响）；
- **中间值**（比如 0.5）→ 这根骨骼**按比例混**。

所以上面那个"半跑半站"的鬼姿势，可以精确地解释为：**腿上的 Mask 是 0.5，所以被稀释了**。把腿的 Mask 全部改成 0，腿就是纯跑步姿势——问题消失。**Mask 就是这个机制的"手术刀"，用哪一刀完全由数值决定。**

> [!warning] Mask 权重 ≠ 姿势混合权重——这是最容易混淆的一处
> 上一篇的 **alpha 是"整个姿势一个数"**：它回答"这次混合整体占多少成分"。
> Mask 的值是"**每根骨骼各自一个数**"：它回答"这根骨骼受不受这次混合影响"。
>
> 两者是不同层级的东西，实际参与计算时**会乘在一起**（下面马上讲）。引擎节点面板上常常并排放着两个 `Alpha` 和 `BlendWeights`，混淆了就会出现"我明明把 alpha 拉到 1 了，腿怎么还在动"或者"我把 alpha 拉到 0 了，怎么什么都没变"。

### 逐骨骼混合怎么算

对每根骨骼，把两个权重相乘，就得到它**实际的混合系数**：

```
实际系数(bone) = 姿势权重 α × Mask(bone)
最终姿势(bone) = A(bone) × (1 - 实际系数) + B(bone) × 实际系数
```

一根骨骼一个循环，互不干扰：

```cpp
// flags: -O0 -g

// 按骨骼混合：同一个 α，被 Mask 逐骨骼改写
void BlendPosePerBone(const Pose& a, const Pose& b, float alpha,
                      const BoneMask& mask, Pose& out) {
    for (int i = 0; i < a.BoneCount(); ++i) {
        // 这就是整个机制的全部：全局权重 × 逐骨骼权重
        float w = alpha * mask.BoneWeight[i];

        out.Bones[i].Translation = Lerp(a.Bones[i].Translation, b.Bones[i].Translation, w);
        out.Bones[i].Scale       = Lerp(a.Bones[i].Scale,       b.Bones[i].Scale,       w);
        // 旋转是球面量，得用 Slerp —— 见上一站
        out.Bones[i].Rotation    = Slerp(a.Bones[i].Rotation,   b.Bones[i].Rotation,    w);
    }
}
```

读这段代码要抓住三点：

1. **`w` 是按骨骼算的**。`alpha` 是全局旋钮，`mask.BoneWeight[i]` 是逐骨骼的旋钮，两者相乘才是这根骨骼身上真正发生的混合量。`mask[i] == 0` 的骨骼，无论 alpha 多大，`w` 都是 0 —— 它**一丝不动**。这正是"腿不被开枪动画污染"的实现。
2. **单根骨骼的插值还是上一站那套**。位置、缩放 Lerp，旋转 Slerp。**Mask 没有引入任何新的插值数学**，它只是给每根骨骼配了一个不同的 `w`。所以上一篇的四元数纪律（[[Notes/动画系统/旋转与变换基础/四元数插值：Slerp与归一化#边界与退化|点积选最短路径、小角度退化]]）在这里一字不改地继续适用。
3. **`out` 是逐骨骼独立算的**。这意味着——这是后面所有坑的根源——**混合后的姿势不保证是一副能站住的骨架**。每根骨骼都算得"对"，整体却可能散架。下一节和「边界与坑」都在处理这件事。

### Mask 怎么划：日常工作量就在这里

机制一行就讲完了，真正花时间的是**这张表上每个 0 和 1 该填在哪**。

#### 做法一：从骨骼层级批量生成（最常用）

骨骼不是一堆散件，而是**一棵树**：骨盆是根，脊柱接在它上面，再往上分出脖子、两条胳膊——每根骨骼只有一个父级，方向永远是父 → 子。**一根骨骼跟着动，它底下的所有子孙都会跟着动**（"动肩膀，小臂和手就一起被带走了"）；Mask 要成片地划，靠的就是这棵树。

人形骨架有个天然的好消息：**上半身恰好是"脊柱往上"的一整棵子树**。所以不必逐根点，只要选一根**分界骨骼**（比如 `spine_02`，从脊柱往上第三节），把**它和它的所有子孙**一次性纳入 Mask。

用上一篇的层级遍历就能做到（[[Notes/动画系统/旋转与变换基础/变换层级与复合变换#层级遍历：世界变换是"从上往下"算的|层级遍历]]）：

```cpp
// flags: -O0 -g

// 从分界骨骼往下，整棵子树打上 1，其余保持 0
void GenerateMaskFromBone(const Skeleton& skel, int rootBone, BoneMask& out) {
    std::vector<int> stack{ rootBone };

    while (!stack.empty()) {
        int i = stack.back();
        stack.pop_back();

        out.BoneWeight[i] = 1.0f;            // 分界骨骼自己也算在内
        for (int child : skel.bones[i].children)
            stack.push_back(child);          // 子孙全部继承
    }
}
```

选 `spine_02` 而不是 `spine_01` 或者 `pelvis`，决定的是**"上半身"从哪里开始算**：分界越低（越靠近骨盆），被替换的骨骼越多，胸部就会更早地跟着开枪动画动；分界太高（比如从脖子开始），开枪时的**肩膀前冲、躯干后坐**都不会被保留，开枪动画看起来像"只有胳膊在动，身体是跑步的身体"。

> [!tip] 实践中的分界通常只在这两三根上挑
> 人形骨架里当分界用的骨骼，实践中就那几个：`pelvis`（整条上身连骨盆一起换，接近全身混合）、`spine_01`/`spine_02`（最常见的上半身起点）、`neck`/`head`（只覆盖头颈，做"边跑边转头看"）。
> 挑的方法不是看名字，而是**播放时观察腰部那一圈皮肤是跟谁走的**——下面那条坑会解释为什么。

#### 做法二：手工刷权重

批量生成解决 90% 的需求，剩下 10% 必须逐骨骼来。典型场景：**只让右臂用 B，左臂保持 A**（右臂举枪射击、左手扶着武器或扶着墙），或者是**双臂上半身但只有肩膀参与**（做"边跑边举盾"）。这类需求在层级上没有一棵子树能表达——右臂和左臂挂在同一个胸骨下——只能一根根指定。

美术工具里这就是一支"骨骼权重笔"，刷完之后这份权重被**另存为一个 Mask 资产**，运行时在混合节点上引用它。

#### 关键实践：Mask 边界处的骨骼要给中间值

这是本篇最值钱的一条，也是"Mask 边界为什么不能一刀切"的直接答案。

如果 `spine_02` 的 Mask = 1、`spine_01` 的 Mask = 0，听起来很干净利落：上半身归 B、下半身归 A。但**皮肤不是按骨骼边界切断的**——模型上每一个顶点早就被美术分配好了"听哪几根骨骼的话、各听几分"，这个分配叫**顶点权重**：`spine_01` 那块区域附近的顶点，是**同时被 `spine_01` 和 `spine_02` 拉着的**（[[Notes/动画系统/蒙皮与骨骼网格/顶点权重与蒙皮算法#权重是什么：每个顶点自带的一张小票|顶点权重]]）。

结果就是：那些"一半听 `spine_01`、一半听 `spine_02`"的顶点最惨——它们的两个"上级"一个被换成了 B 的姿势、一个还留在 A 的姿势，自己就成了两块姿势之间的夹心，**被硬生生拉长**。整圈这样的顶点连起来，模型在腰部**裂开一条缝**：上半身已经跟着开枪动画转过去了，腰部皮肤还在跟着跑步的骨盆走，中间那一圈被撕成两截，表现是**一条尖锐的折痕 / 撕裂缝，转身和弯腰时最明显**。

修法很直接：**分界处给中间值**。`spine_02` 给 1、`spine_01` 给 **0.5**，让这一节骨骼本身处于"一半 A 一半 B"的状态，上下两块之间就有了过渡带，皮肤顺着转过去。给多少取决于这段骨骼在骨架上的"厚度"——脊柱这类粗骨骼通常要从分界点**往上或往下溢出一到两节**，而不是戛然而止。

> [!warning] Mask 的边界就是"折叠线"，不是骨骼边缘
> 想象你拿画布对折：折痕落在哪儿，哪儿就有痕迹。Mask 的分界就是这条折痕，**过渡带越窄，折痕越尖**。手指、脚趾这类细骨骼可以切得很硬（相邻骨骼的皮肤区域本来就重叠少）；骨盆到脊柱这一段千万不能硬切。

### Mask 绑的是 Skeleton，不是角色

Mask 的实现是**一张按骨骼数组下标（index）索引的表**——就是开头那句"第 3 号骨骼"里的序号。**序号的编排权在 Skeleton 手上**，这个细节带来一个必须知道的后果：

> **Mask 和某套 Skeleton 强绑定。换骨架时，同一张 Mask 按同样的下标去取值，取到的却是别的骨骼。**

具体表现就是：**"Mask 在这个角色上调得好好的，换了个角色（或者骨骼多寡不同的模型）一用，上半身的划分就完全不对了"** —— 比如原本该被替换的肩骨现在没被替换，反倒是不该动的某根手指骨在跟着 B 动。

根因有两层：不同角色的**骨骼数量可能不同**（Mask 长度直接对不上），即使数量一样，**骨骼的排列顺序也未必相同**。所以跨角色复用 Mask 的前提是：这些角色**共用同一套 Skeleton 资产**（这是正确做法），或者 Mask 按骨骼名而不是下标去映射（有些管线会这么做，代价是每次加载要做一次名字查找）。

这条也是"重定向"话题的一块拼图。**重定向**是另一回事：把一套动画整体复用到身材比例不同的另一个角色身上（[[Notes/动画系统/动画数据与采样/动画重定向：一套动画复用到不同骨架|动画重定向]]）。它搬得动的是**姿势**——而 **Mask 不会自动跟着重定向**：姿势被搬到了新骨架上，Mask 还指着一堆旧序号，于是覆盖范围默默错位。**所以重定向做完，必须重新检查一遍 Mask 覆盖的是哪些骨骼。**

### 上下半身混得"不走样"的前提：共享根骨骼

最后一条是最容易被忽略、后果最"玄学"的规则。

（零假定：**骨盆（pelvis）**是躯干最下面那块骨头，也是整副骨架位置上的老大——**角色整体的位置和朝向，实际上就记在它（或它之上的根骨骼）身上**，全身上下的关节都挂在它底下，跟着它走。所以在动画数据里，跑步时骨盆有起伏、有左右摇摆，那是整具身体"往前跑"这件事在数据里的样子。）

上下半身各用各的动画时，**两根驱动链会争夺同一根骨骼的控制权**。最典型的就是骨盆：跑步动画里它一直在动；开枪动画如果是从站立做的，它的骨盆是静止的——而开枪动画同样也长在骨盆上。

于是不管 Mask 怎么填、权重给多少，结果都不对：

- **Mask 没把骨盆锁住**：**静止也是一种姿势**。权重只要不是 0，骨盆就被"站着的骨盆"和"跑着的骨盆"平均掉一部分，跑步的起伏幅度直接打折。
- **Mask 把骨盆锁给了下半身，但上半身动画的根骨骼不是这根骨盆**（比如它自己从胯部另起了一根）：上半身的位移传不到"共用的那根"上去，两边各走各的，身体在中段错位。

两种取法各有各的坏法，但结论一样——**骨盆不该交给两次混合共同决定**。后果是两联动的：

- **身体被撕开**：髋部与双腿的接触关系错位，视觉上腰部像被拉开了一道口子，或者髋部的旋转和腿的朝向不一致。
- **脚滑**：骨盆是整个下半身的根，它一错，腿的着地点跟着错，脚在地面上滑动。

所以上下半身混合有一条工程惯例：

> **骨盆（以及它以下的整条腿链）只由下半身的动画驱动；上半身动画的根骨骼必须与下半身共享同一根骨盆。**

```cpp
// flags: -O0 -g

// 骨盆及以下一律归下半身：Mask 里把这些骨骼强制锁 0
// 上半身动画即使长在骨盆上，也不允许它改写骨盆
void LockCommonRoot(BoneMask& mask, const Skeleton& skel, int pelvisIdx) {
    std::vector<int> stack{ pelvisIdx };   // 骨盆 + 整条腿链 + 根骨骼
    while (!stack.empty()) {
        int i = stack.back();
        stack.pop_back();
        mask.BoneWeight[i] = 0.0f;         // 只由 A（下半身）驱动
        for (int child : skel.bones[i].children)
            stack.push_back(child);
    }
}
```

这也顺带解释了日常调动画时一个高频困惑：**"上下半身混合以后，角色整体位置开始飘 / 开始滑"** —— 十有八九是上半身那段动画的根骨骼没和下半身对齐，它带来的位移被算进了最终姿势。检查顺序很简单：先看 Mask 有没有把骨盆和根骨骼锁住，再看上半身动画的根骨骼是不是就是那根骨盆（而不是从胯部或某一个中间节点另起的）。

## 边界与坑

- **Mask 全 0**：完全退化成"不混合"，输出就是 A。表现是**加了 B 的节点之后画面一点变化都没有**——排查"节点没生效"时，第一个要看的就是 Mask 是不是空的（或者被误刷成了 0）。
- **Mask 全 1**：退化成"整体替换"，等于上一篇的普通混合。表现是**上半身对了，但腿也一起被 B 覆盖**，也就是本篇开头那个"半跑半站"的姿势——只不过这次是彻底地站住。
- **Mask 未覆盖的骨骼**：新加了一根骨骼（比如给角色补了根手指骨、尾巴骨）而 Mask 是之前存的，那根新骨在 Mask 里**没有对应项，通常按默认 0 处理**，也就是"保持 A"。
  表现就是：**新加的那根骨骼死活不动**，明明动画里它有动作，角色身上就是看不见。这是"改完骨骼之后动画坏了"的经典原因之一，**加骨骼后要回头检查所有 Mask**。
- **父子骨骼 Mask 权重跳变**：上面讲过的腰部硬切口。判别方法很简单——**如果一条裂纹出现在某根骨骼的位置上，就去看这根骨骼和它父骨骼的 Mask 值差多少**，差值大就是它。
- **上下半身根骨骼/骨盆不一致**：身体被撕开、脚滑、整体飘移。原则是**共享骨盆，骨盆只由下半身驱动**。
- **Mask 与姿势权重搞混**：节点上同时有姿态 alpha 和逐骨骼 Mask 时，"没效果"和"效果过猛"两种误判几乎都来源于此。记住基数关系：**实际混合量 = 姿势权重 × Mask 值**，两者任何一个为 0，这根骨骼就完全不受影响。
- **Mask 绑定骨架索引**：换角色 / 换 Skeleton 时必须重新核对，跨角色复用需要共用同一套 Skeleton 或按骨骼名重映射（详见上一节）。

## 参考实现（UE）

| 引擎 | 对应模块/数据结构 | 具体体现 |
| :--- | :--- | :--- |
| UE | `FAnimNode_LayeredBoneBlend` | 分层骨骼混合节点，就是本篇的"按骨骼混合"。它的 `LayerSetup` 里存着每一层的 `FInputBlendPose`（`FBranchFilter` 的数组），`BlendWeights` 是每一层的姿势权重；逐骨骼权重算在 `FPerBoneBlendWeight` 数组里，由 `Evaluate_AnyThread` 消费。节点类在 `AnimGraphRuntime` 模块的 `AnimNodes/` 下——见 [[Notes/UE/第四阶段-客户端运行时层/UE-AnimGraphRuntime-源码解析：动画图与BlendSpace\|UE 动画图与 BlendSpace]] |
| UE | `UBoneMaskFilter` / `FBranchFilter` | Mask 在 UE 里的落地：分层混合节点用 `FBranchFilter`（对某根骨骼**及其子孙**批量处理）与 `FInputBlendPose` 描述遮罩，更早的资产型遮罩是 `UBoneMaskFilter`。**这套遮罩存的是"骨骼名字 + 层级深度"（`FName BoneName` + `int32 BlendDepth`），不是一份按下标排的权重数组**——所以它是本篇"按骨骼名而不是下标去映射"那条替代方案的落地形态，天然免疫"换骨架错位"；而真正带逐骨骼 0~1 浮点权重的形态是 `UBlendProfile`（`SetBoneBlendScale` 支持 `bRecurse` 整棵子树一起刷，正是"做法一"）。**没有** `USkeleton::GetMeshBoneMask` 这种入口，别去找 |
| UE | `FAnimationRuntime::BlendPosesTogetherPerBone` | 运行时执行逐骨骼混合的函数：把每个姿势的权重**逐骨骼改写**后混合多路姿势（典型上下文是混合空间与分层混合），把"姿势权重 × 逐骨骼权重"这套算法集中在一处实现；骨骼级权重的承载结构在 AnimationCore 里是 `TBoneWeights<Adapter>` 模板类（权重以 `uint16` 量化存储、支持 `Blend(A, B, Bias)`）——见 [[Notes/UE/第四阶段-客户端运行时层/UE-AnimationCore-源码解析：动画系统总览\|UE AnimationCore 动画系统总览]] |

## 一句话总结

Mask 是一张**逐骨骼的 0~1 权重表**：把"整个姿势一个权重"升级成"每根骨骼各自有权重"，实际混合量 = 姿势权重 × Mask 值，于是上半身可以整块换成开枪姿势而腿保持跑步；划分 Mask 通常从一根分界骨骼往下整棵子树取，但**分界处必须给中间值**（否则腰部皮肤会裂开），并且**骨盆只能由下半身单方面驱动**（否则身体会被撕开或脚滑）——而这一切都绑在某套 Skeleton 的骨骼索引上，换骨架就得重做。
