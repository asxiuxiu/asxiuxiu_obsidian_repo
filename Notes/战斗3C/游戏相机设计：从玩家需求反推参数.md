# 游戏相机设计：从玩家需求反推参数

这篇笔记源于一次自我怀疑：做过很多相机功能（加配置、接 track 相机、接船相机表），但被问"让你从零设计一套相机，你做得来吗"时，脑子里只有一堆说不清的参数名。聊完之后发现，问题从来不在能力，在于**学习方向反了**。

## 我曾经以为：设计相机 = 精通每个参数的含义

我脑子里存着一堆参数名：`camera_target`、`camera_target_rightward_offset`、`camera_lag`……我试图从参数出发，背下每个是干什么的，以为背熟了就会设计了。结果越背越像浆糊。

实际上设计者是**反着活**的：

> **相机参数从来不是背出来的，是从"这一刻玩家需要知道什么、感受到什么"反推出来的。参数表只是需求的物化。**

策划说"疾跑时感觉不对"，设计者听到的不是"改哪个数"，而是"疾跑时玩家的需求变了"——然后参数只是这个判断的自然结果。

## 心智模型：跟拍摄影师

把所有相机参数统摄起来的一个比喻：

> **把相机想象成一个扛着摄像机的跟拍摄影师，所有参数都是在给这个摄影师下指令。**

这个摄影师每帧都在回答几个问题，参数表就是他的工作手册：

| 参数家族 | 摄影师的问题 | 常见参数 |
|---|---|---|
| 站多远 | 我离演员多远？ | arm length（弹簧臂长度，弹簧臂是引擎里一根虚拟的"自拍杆"，相机装在杆尾，杆长决定镜头距离） |
| 看谁 | 镜头对准谁、对准身体哪个点？ | camera_target、各种 offset（构图偏移） |
| 跟多紧 | 演员突然动了，我多快反应过来？ | camera_lag（滞后，详见 [[Notes/战斗3C/相机滞后：表现力与操控感的拔河]]） |
| 怎么换机位 | 换拍摄方案时，瞬移还是滑过去？ | Blend（混合）时长与曲线，见 [[Notes/战斗3C/相机状态机：常态状态的划分与组织]] |

比如"疾跑要换一套参数"，翻译成摄影师语言就是：演员跑起来了，导演喊"往后退两步，镜头压低点，跟得松一点"——**换状态 = 换一套指令，Blend = 摄影师从旧姿势滑到新姿势而不是闪现过去。**

## 五场博弈：相机系统的场景地图

一个 3A 相机系统要处理的场景看似杂七杂八，其实可以归成五场博弈——相机永远在跟五个对手谈判：

1. **跟角色状态博弈**：走、跑、跳、上马、载具……每个状态一套参数 + Blend 表。入门课，也是地基，详见 [[Notes/战斗3C/相机状态机：常态状态的划分与组织]]。
2. **跟敌人博弈**：锁定后画面里有两个主角，构图要同时装下玩家和敌人；大体型 Boss 是这道题的极限形态，详见 [[Notes/战斗3C/Boss战相机：巨物感与可读性的矛盾]]。
3. **跟环境博弈**：角色退到墙角，相机理想位置在墙里——穿墙？拉近？把墙变透明？这是生存战，3A 和普通项目的差距一大半体现在这场仗打得干不干净。（待挖）
4. **跟玩家注意力博弈**：真人摄影师牛在预判而不是反应快。角色向右加速，镜头应提前把构图往左挪，让运动方向留白（电影术语叫 lead room，在运动方向上多留画面空间）。`camera_target_rightward_offset` 干的就是这个：构图不是对准角色，是对准"角色加上他的意图"。
5. **跟情绪博弈**：受击抖动、处决运镜、冲刺 FOV kick——相机在这里不是记录者，是导演。（待挖）

## 3A 质感是什么

> **好相机是隐形的。玩家从来不会夸"这相机做得好"，他们夸的是"这游戏手感真好""打击感真强"——这里面一半的功劳是相机的。**

拆开是三根柱子：

- **不犯错**：99% 的时间大家的相机都是对的，差距全在那 1%——穿墙没？跳变没？抽风没？质感的第一要义是"永远不出戏"，是几百个边角情况被一个个磨平的耐心。
- **会预判**：平庸的相机是"反应"，角色动了镜头才动；好的相机是"预测"，总先一步到玩家想看的地方。玩家说"这镜头好舒服"却说不出为什么，原因就在这。
- **每一次抖动都是故意的**：shake、顿帧配合、处决运镜，全是分镜级的导演决策，幅度精心调校。

## 这场讨论本身教我的

出发时我问"我是不是一个很菜的战斗 GP"。聊完发现：我建过相机状态机 + Blend 表 + track 相机 + 船相机表——**我已经建过一栋房子了，只是以为自己只是在搬砖。** 缺的不是能力，是"从需求反推参数"这个视角，以及把做过的功能重新命名、归位的梳理。
