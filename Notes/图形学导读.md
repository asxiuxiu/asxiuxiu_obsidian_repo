# 图形学导读

> **这份导读是"地图"，不是"攀岩路线"。** 它不带你精通渲染，而是让你作为一个不搞渲染的人（比如 GP/玩法程序员），也能看懂渲染的世界在发生什么，以及当战斗掉帧、画面不对时，你扒开工具能看懂到什么程度。
>
> 完整、纵深的技术笔记已归档在压缩包 `archive/graphics-rendering-archive-*.zip`（含计算机图形学专栏）。本导读把其中最有用的概念，用外行人能懂的语言重新讲一遍。

---

## 一句话理解"渲染"

**渲染（Rendering）＝ 用数学把 3D 世界变成 2D 图片。**

你电脑里装了个"虚拟摄影棚"：有模型（演员）、有材质（皮肤的纹理）、有光源（灯光）、有相机（镜头）。渲染就是让 GPU 按下"怎么把这一切拍进一张 2D 画面"的按钮——而且每帧要重新拍一次（60fps = 每秒重拍 60 次）。

对你的意义：游戏里玩家看到的一切"画面效果"，都是这一套摄影流程算出来的。你调战斗手感时碰到的"这个闪屏""这个血条发白"，根源往往就藏在这一套流程某一步里。

## 你必须认识的核心概念（外行版）

### 1. Shader（着色器）——给每个像素发"妆容"的代码

- **是什么**：一段小代码，决定"屏幕上每一个点该是什么颜色、多亮"。GPU 用它对成千上万个点同时执行（并行）。
- **外行类比**：每颗尘埃都配了一个化妆师。化妆师看到"这个点离光源多近、方向朝哪、什么材质"，就决定它长啥样。
- **你只需知道**：画面不对劲（太亮/太黑/发紫），多半是 shader 里某句逻辑/某个参数出错。你不是去改它，而是知道"我得叫渲染同学看 shader"。

### 2. 纹理（Texture）——贴在模型表面的"贴纸"

- **是什么**：一张 2D 图片，被"贴"到 3D 模型表面，让模型有颜色和细节（皮肤纹理、砖墙纹路）。
- **外行类比**：给一个白色 3D 头像"贴"上肤色照片，它就活了。
- **关键技术词**：UV 坐标（告诉图片哪一块贴到哪）、Mipmap（远处的图用模糊小图省显存）、压缩纹理（省显存）。
- **你只需知道**：模型"没贴图/显存爆/远处发闪"，都是纹理这一层的问题。掉帧常因显存爆了。

### 3. 材质（Material）——定义"这张皮怎么反光"

- **是什么**：纹理只是"颜色"，材质是"这套皮的完整设定"——它粗糙还是光滑？金属还是塑料？能透光吗？
- **外行类比**：同一张黑色贴图，配"粗糙材质"是磨砂黑，配"光滑材质"能反射周围环境。
- **你只需知道**：你在引擎里调的 "材质参数"（金属度/粗糙度/自发光）最终就是色道给渲染层看的一串数字。特效"塑料感""太亮"基本都在这一步调。

### 4. Draw Call / 合批（Batching）——"一次喊话画一堆东西"

- **是什么**：每次让 GPU "画这个物体"就是一次 Draw Call。喊话太多，CPU 先累死。
- **外行类比**：与其让 1000 个工人每人单独领一张图纸（1000 次喊话 + 排队），不如让他们一次领 1000 张图一起干（合并成 1 次）。
- **你只需知道**：**战斗一掉帧，第一嫌疑就是 Draw Call 太多**（视角里物体/特效太多）。这是 GP 优化最常碰的坎。

### 5. RenderPass / 渲染管线（Pipeline）——"一帧要分几步画"

- **是什么**：一帧不是一次画完的，而是分成好几个阶段。每个 Pass 是一步，前一步的成果喂给下一步。
- **外行类比**：拍电影不是一镜到底——先拍实景，再叠特效层，再调色，最后打包输出。渲染也是：先画场景，再补光、加雾、加后期滤镜。
- **你只需知道**：为什么"后处理黑屏""特效叠不出来齐"——因为某一步 Pass 依赖前一步，顺序/依赖错了就出事。

### 6. 光照（Lighting）——在 3D 里"调灯"

- **是什么**：决定物体亮暗、颜色、阴影的光源计算。从简单的平行光/点光，到复杂的全局光照（光在场景里到处反弹）。
- **你只需知道**：场景"一片死黑""物体塑料感"，都在光照这层。战斗里想突出某个角色/特效，也是靠这层点亮某处。

### 7. 后处理（Post-Processing）——最后套在整张画面上的滤镜

- **是什么**：整个画面渲染完，再整张图加工：泛光（Bloom）、画面震动、暗角、扭曲、色彩校正等。
- **外行类比**：视频 App 的滤镜/美颜——不是改原片，而是在成品上套一层效果。
- **你只需知道**：很多"爽快的游戏反馈"（射击的泛光、受击的画面震动）都是后处理做的。这也是性能重灾区。

## 重点答疑：外行人能不能读懂 RenderDoc？

**能，而且能利用它做不少事。** RenderDoc 是一个"抓帧"工具：按下它，它把游戏某一帧的"整个渲染过程"像监控录像一样录下来，你可以事后一帧一帧地看 GPU 到底干了什么。关键问题是"你能看懂到什么层次"——分两层：

### 第一层：外行人能轻松看懂（强烈推荐学）
你不需要懂渲染原理，直接用就行：

- **看一帧画了几次 Draw Call**（总次数、哪些物体画了）。→ 判断"是不是物体太多导致掉帧"。
- **看每一帧的渲染目标 / 纹理 / 截图**：能逐 Pass 看到"场景图""阴影图""深度图""最终画面"分别是啥样。→ 判断"是哪一步把画面搞坏了"。
- **看 GPU 每个 Pass 的耗时**：哪个 Pass 最烧算力。→ 定位"掉帧卡在哪一步"。
- **看资源列表**：这张图占多大显存、这个模型多少顶点。→ 查"显存怎么爆的"。

**这一层，你完全能靠直观学会**——就像你不会修车也能看懂仪表盘哪个灯在报警。

### 第二层：需要图形学功底才能深入（这一层留给渲染同学）
- 逐条看 shader 的输入寄存器、常数缓冲内容、反汇编指令。
- 分析顶点光栅化细节、采样器配置、内存布局优化。
- 判断"某个 Pass 是不是有过度绘制（overdraw）"的深层次原因。

**这一层不是你的活。** 你的正确姿势是：用第一层看懂"问题出在哪个 Pass / 是不是多画了东西 / 是不是爆显存"，然后把结论抛给渲染工程师深挖。

> **给 GP 的实用总结**：RenderDoc 是你的"体温计"，让你在不深入渲染的情况下确认"这个画面问题大概在哪一段、性能卡在哪一段"。具体药方由渲染同学开。

## 这些概念和你的战斗/3C/动画工作的接口

| 你在工作时碰到的现象 | 背后渲染概念 | 你该看哪层 |
|---------------------|-------------|-----------|
| 战斗掉帧、特效一多就卡 | Draw Call / 合批、显存 | RenderDoc 看 Draw Call 数、显存占用 |
| 角色受击画面震动、泛光 | 后处理 | 看后处理 Pass 耗时 |
| 某角色"塑料感/太亮太黑" | 材质、光照 | 看材质参数、光照配置 |
| 特效叠不出来/顺序错 | RenderPass 依赖 | 看渲染目标顺序 |
| 模型没贴图/发白 | 纹理、材质 | 看纹理资源是否加载 |

## 补：AI 在图形渲染中的角色（跨域）

渲染这一行也在被 AI 改写。你不需要会实现，但值得知道这些技术存在，它们和你的 AI + 游戏方向有关联：

- **3D Gaussian Splatting（3DGS）**：用一堆"高斯球"表示场景，比传统网格更能表达实拍/重建场景，可实时渲染。你看到的 AI 生成的 3D 内容可能走这条路。
- **神经纹理压缩（NTC）**：用神经网络把贴图压成更小的特征数据，Shader 里实时解码，省显存。
- **神经网络降噪**：光追/路径追踪画面很噪，用神经网络去噪。是现代渲染管线里 AI 的成熟落地。
- **AI 辅助 3D 资产生成**：文本/图片 → 扩散模型 → 网格/高斯球，正在改变游戏资产生产。

> 这些技术的详细笔记在归档压缩包中。对你的意义：**AI 生成的内容（模型、动画、场景）最终都要被"塞进"渲染管线画出来**——你懂这条管道，就知道怎么把 AI 产物接进游戏。
